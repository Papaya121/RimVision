# Итоговая карта владельцев RimVision

[Документация](../README.md) · [История рефакторинга](../Archive/Refactoring/README.md)

## Репозиторий без Unity Editor

`Version.txt` –  единый источник отображаемой версии основного мода и Multiplayer-аддона. `Build.ps1` подставляет её в шаблоны описаний About и локализаций основного мода только в staging. `CompatibilityDescription` сохраняет владение русским описанием Multiplayer и читает версию один раз из ресурса своей DLL, встроенного из того же файла. Версия API и версии сборок этим файлом не задаются.

Игровые исходники находятся в `Source/RimVision/Runtime`, аддоны –  в `Source/Multiplayer`, `Source/Compatibility`, `Source/ThirdPerson`; ресурсы пакетов –  в `Mods`. Упаковкой и staging владеет корневой `Build.ps1`: компиляция основной DLL выполняется один раз, аддоны используют ту же сборку, в отдельные пакеты попадают только их собственные DLL. Генерацией прежних XML LOD в staging владеет `Tools/Models/ModelLods.cs`, использующий System.Numerics без UnityEngine. Готовый shader bundle принадлежит `Mods/RimVision/ShaderBundles`, исходники –  `Shaders`; обычная упаковка bundle не пересобирает. Игровые владельцы состояния, lifecycle, сетевые и API-контракты не изменены. Старые пути Assets/ModBuild ниже относятся к истории до переноса; соответствие путей приведено в [отчёте о переносе](../Archive/Migration.md), актуальная структура –  в [корневом README](../../README.md).

Локальный исключённый из Git `BuildShaders.local.ps1` владеет служебным Unity-проектом и логами в `.shader-build`: копирует актуальные `Shaders`, собирает прежний Windows64 bundle с ChunkBasedCompression и заменяет `Mods/RimVision/ShaderBundles/rim3d-shaders` только после успешного завершения Unity. Предыдущий bundle сохраняется в папке соответствующего запуска. Обычная упаковка `Build.ps1` этот процесс не запускает.

Установкой выбранных собранных пакетов также владеет `Build.ps1` при `-Install`; локальная исключённая из Git `start.bat` запускает этот режим. Установщик готовит все пакеты до замены, проверяет packageId, сохраняет PublishedFileId и прежние версии в `RimWorld/RimVisionBackups`; при ошибке замены восстанавливает уже заменённые папки. Устанавливаются только пакеты из прежнего списка сборщика; прочие моды и исходный контент репозитория не меняются.

`start.bat` также передаёт `-Launch`: `Build.ps1` запускает RimWorld из того же GameRoot только после успешного завершения установки. Без этого параметра обычные сборка и установка игру не запускают.

Служебный проект сборки шейдеров явно включает встроенный `com.unity.modules.assetbundle`. Перед заменой файла локальный сборщик загружает полученный bundle и проверяет количество Shader-объектов; успешного завершения BuildPipeline недостаточно для публикации результата.

## Структура Runtime

`ObjectPresentation` владеет кэшем полной 3D-геометрии и дальних 2D-карточек статических optional-моделей по чанкам. Оба варианта готовятся при загрузке и пересборке изменённого чанка; движение камеры только переключает готовые объекты. Промежуточные LOD отключены: библиотека не читает autoLods, настройки LOD скрыты, животные также используют полную модель до перехода к дальней карточке. Старые Scribe-ключи настроек сохранены для совместимости. Инвалидация, очистка чанков и общий registry ресурсов остаются прежними; игровые состояния и Multiplayer-команды не меняются.

`HudPresentation` владеет списком ванильных кнопок и прокруткой раздела колонии в меню Tab. `ActionMenus` открывает их через штатный MainButtonWorker, сохраняя временный слой окон и его восстановление. При выборе мира или ванильных проектов `PreviewWindow` временно скрывает 3D-окно и освобождает ввод/камеру по WorldRendererUtility.WorldSelected и MainTabsRoot.OpenTab; общий контроль ввода MapView блокирует управление пешкой. Сеанс управления сохраняется, отдельного флага нативного вида нет; обработка окна не зависит от перехвата UpdateMode в Multiplayer.

`WeatherParticlesRenderer` владеет локальным временем анимации осадков и накопленным сносом ветром. Они обновляются по игровым тикам (тикам карты в Multiplayer), скрытие сбрасывает точку отсчёта тиков, Dispose очищает состояние. WeatherParticles отсекает частицы у ближней плоскости до растеризации. Состояние симуляции, сохранения и владение ресурсами не меняются.

`WorldGeometry` выбирает гибкость растительности, `ObjectPresentation` применяет её к штатным дополнительным моделям и их дальним карточкам. `Geometry` хранит корень и отрицательную гибкость в UV4 (нулевые/отсутствующие данные исключают деформацию), загружает их в прежний mesh и расширяет bounds под максимальное отклонение. `WeatherRendering` задаёт локальный shader global силы ветра из WindManager; пространственный рендер восстанавливает его вместе с остальными погодными globals. `PlantWind.cginc` объединяет деформацию поверхности, глубины, проекционных теней и обводки: корень закреплён, крыша подавляет ветер. Новых материалов, объектов сцены, игровых состояний и сетевых контрактов нет; меши освобождаются прежним владельцем.

`StatusMenuPause` остаётся владельцем сохраняемых списков игроков и открытых меню статуса. При FinalizeInit в Multiplayer он регистрирует единственную глобальную `PauseSession` через ISessionManager; сессия наследует ExposableSession, сохраняется и восстанавливается менеджером Multiplayer и только читает прежнее условие общей паузы. Старые Scribe-ключи и синхронизированные команды не меняются; старые сохранения получают сессию при инициализации. Ресурсов сцены и отдельного флага паузы нет.

Исходники в `Source/RimVision/Runtime` сгруппированы по основному назначению файлов:

| Каталог | Содержимое |
| --- | --- |
| `Core` | Запуск 3D-вида, интеграция с RimWorld, настройки и мост Multiplayer |
| `Editor` | Запуск, песочница и отладочные подписи для Unity Editor |
| `Control` | Управление пешкой, камера, ввод, назначения клавиш и захват мыши |
| `Actions` | Ручные взаимодействия, работа, перенос, бой, лечение, строительство и зоны |
| `Orders` | Колониальные приказы, выбор инструментов и колонистов, меню и предпросмотр |
| `UI` | HUD, отображение активности, панели состояния, эффекты самочувствия и оверлеи осмотра |
| `Rendering/World` | Геометрия построек, чанки, грязь, крыши, грунт и вода |
| `Rendering/Models` | Модели объектов и пешек, генерация объёмов и оружие первого лица |
| `Rendering/Environment` | Освещение, небо, снег, погода и пространственный звук |
| `Rendering/Effects` | Эффекты боя, взрывов, огня, газов, орбитальных атак и обводка |
| `Spatial` | Связанные пространственные карты, их отрисовка, выбор целей, снаряды и соседние карты |
| `Minigames` | Общая система миниигр, награды и реализации отдельных игр |
| `API` | Публичные контракты, регистрации, расширения и их интеграция с игровым видом |

Папки служат для навигации: файлы с частями `partial`-классов сохраняют прежние пространства имён, типы и владельцев состояния. `Rim3D.csproj` подключает все исходники рекурсивно через `Runtime/**/*.cs`.

## API 1.6: расширенные контракты (исходники, без сборки/запуска)

ViewInput остаётся владельцем опроса и transient значений осей/жестов, поглощения и ошибок. SetControlAxis разрешён только при dispatch callbacks и накапливает локальный ввод кадра. Прежние PawnControl/Multiplayer исполняют движение; прямого изменения мира из callbacks нет. ModSettings владеют отдельными назначениями модификаторов, deadzone/invert. Штатный mouse input читает тот же набор поглощённых кнопок/осей.

ViewCamera владеет RimVisionCamera.Session: выбранным primary, жизненным циклом активных провайдеров, исходной позой перехода и неактивными профилями дистанций. Активная дистанция остаётся только в ViewCamera; профили сохраняют значение лишь на время отсутствия владельца. Session закрывается при demote/Dispose до освобождения сцены. Проверка CollisionRadius использует существующий пикер и девять лучей, не создавая физическую сцену.

RimVisionJobs владеет слабой transient связью нативного Job и tracked API request. JobDriver Notify_Starting/Cleanup и JobMaker.ReturnToPool сообщают фактический исход без замены нативной работы. Смена Game и нативный ClearAllMapsAndWorld очищают трекеры; новых Scribe-ключей нет. Общий command context MapView доставляет локальные JobChanged/обновляет ticket отдельно от ActionCompleted. MP owner/token фильтрует результаты; NativeSimulation различает обычный авторитетный тик MP и интерфейс. Callback не исполняет следующий Job синхронно.

ActionMenus владеет выбранным API interaction и временем подтверждения удержанием. Провайдер задаёт только описание уже зарегистрированного действия; доступность и исполнение используют прежние валидаторы/очередь. HudPresentation рисует отдельный элемент Interaction. Нативные tools/menus и специальные режимы сохраняют свой порядок; локальный таймер не является нативным warmup.

ObjectPresentation владеет экземплярами пользовательских моделей, их Root и явно переданными ресурсами, обновлением/инвалидацией штатной геометрии. RimVisionModels владеет лишь регистрациями. Дополнительные визуальные слои имеют собственные экземпляры; simulation-only сцены ничего не создают. PickingBounds принадлежат визуальному экземпляру и читаются прежним ViewTargeting; игровые размеры/снаряды не меняются.

`ObjectPresentation` вычисляет поворот 3D-деревьев и разброс масштаба ±8% из стабильного thingIDNumber без RNG и дополнительного состояния. Отрисовка и raycast модели используют один поворот и масштаб; LOD сохраняют масштаб исходного дерева. Результат одинаков для одного ID в SP/Multiplayer и после загрузки; игровые Rotation, размеры, сохранения и сетевые команды не меняются.

RimVisionView владеет временными эффектами и Sustainer handles, обновляет их перед BeforeRender и закрывает до общих ресурсов. Стационарные объекты принадлежат своей Map, прикреплённые используют прежние attachment visibility; аудио остаётся нативным. ExtensionSession владеет очередью AnimationEvent и Lifecycle callbacks, включая Closing до Dispose. Нативный урон/смена оружия дают события, Reload/Ability сообщаются их владельцем; renderer механику не угадывает.

ApiRegistry остаётся владельцем состава/порядка регистраций и их Revision. RimVisionDiagnostics читает их снимки и хранит ограниченные последние ошибки, без зеркала действующего игрового состояния. RimVisionCapabilities владеет описаниями возможностей/версий внешних контрактов и кэширует fingerprint по revision. Отдельный MP ApiContract сообщает локальное несовпадение; его результат не меняет ветвление симуляции. Это диагностика, а не новая система синхронизации или замена штатной проверки модов.

## API 1.5: представление, ввод и подтверждение команд (исходники, статический разбор)

`ModBuild/ThirdPerson` –  отдельный устанавливаемый аддон камеры на публичных RimVisionCamera/RimVisionInput. ThirdPersonMod владеет process-lifetime регистрациями и локальным переключателем первого/третьего лица; дистанция, поза, столкновения камеры и aim ray остаются у ViewCamera. Аддон не создаёт Unity-ресурсы, не меняет Jobs/сохранения и не добавляет сетевой протокол. Сборка аддона ссылается на ту же DLL API 1.5, которая устанавливается в основной мод.

`ViewCamera` остаётся единственным владельцем позы, углов, дистанции и последнего camera frame/aim ray. `RimVisionCamera` владеет только регистрациями primary/modifiers; кадр применяется после прежнего CameraPose и перехода, затем существующий ViewTargeting ограничивает отступ и выбирает точку прицеливания. Штатная камера, аудиослушатель, ввод и рендерные ресурсы не передаются провайдерам. SpatialAudio использует необязательную ListenerPose того же кадра без нового AudioListener. Третье лицо отделяет визуальную камеру от origin выстрела и MovementYaw; физическая/сетевая проверка атаки остаётся у CombatActions/нативного провайдера.

`RimVisionPresentation` выбирает primary отдельно по Channels и применяет modifiers. PawnAppearance владеет применением PawnAnimation/Scale и прежней ходьбой; FirstPersonWeaponRenderer и HeldThingPresentation владеют WeaponAnimation, кистями и визуальным дулом в своих проходах. Исходные точки хвата и последнее визуальное дуло имеют разные роли: первые восстанавливают базовую позу, второе читается эффектами. Собственные FPV Mesh/Material заимствованы; MaterialPropertyBlock не меняет их материал. RimVisionView владеет созданными привязками объектов и прежним cleanup; пользовательские иерархии/анимации частей тела остаются у расширения.

`HudPresentation` владеет разметкой элементов и их Bounds/InputBounds. Character HUD разделён на те же штатные отрисовки портрета, оружия, колонистов, здоровья, боли и выносливости; новые callbacks обрамляют их, не добавляя игровых мутаций. `RimVisionHud` хранит только регистрации. ViewInput владеет локальными held/consumed/error состояниями клавиш аддонов; Rim3DSettings хранит назначения по ID и прежний BindingsVersion. Блокировки каналов по handle принадлежат RimVisionView и агрегируются его сессией; отдельного флага захвата курсора нет. MapView задаёт прежний порядок и применяет ограничения.

`RimVisionExtensionSession` остаётся владельцем Previous-снимков, доставки локальных событий и изоляции callback. `RimVisionRequests` –  часть общего command context MapView: очередь навигации, ожидание tracked request и доставка результата после локальных callback. Старые и новые запросы используют одни TryExecuteExtensionAction/TryApplyLayerAction; новых игровых владельцев состояния не вводится. Pending tickets при закрытии SP отменяются, в MP отсоединяются от UI без обещания отмены уже отправленной команды.

`PawnControl` владеет transient native axes и binding. SupportsContainedActor требует настоящую цепочку ParentHolder до spawned Carrier; SupportsVerticalMovement сохраняет нативный Y. Нативный мод сохраняет отношения, позицию, Jobs и ресурсы. SP/MP selection и sessions разрешают карту через RimVisionControl.MapFor. Обычные пешие взаимодействия пассажира не вызываются; registered actions и нативный бой сохраняют прежнюю границу исполнения.

`CombatActions` владеет одним transient циклом фаз атаки, исходным провайдером, aim offset и сроком входных данных. SP MapPostTick и MP ControlSessions вызывают Held на симуляционных тиках; lifecycle вызывает Cancelled у исходного провайдера. Нативный мод остаётся владельцем заряда, очереди, боеприпасов и сохранений. API request, native axes и combat input имеют отдельные MP sync methods/workers с owner/token проверкой; прежние Rim3DCommand, ControlInput и Scribe-ключи не расширены. Simulation-only контексты по-прежнему не создают визуальные расширения, HUD или Unity-ресурсы.

## Пространственный API 1.4 (исходники, статический разбор)

`SpatialMapRendering` готовит загруженную группу при начальном открытии 3D; новые сцены продолжают готовиться по кадрам. `RimVisionView.PrepareLayer` только приоритизирует локальную подготовку, не генерирует игровые карты и не назначает Jobs. `RimVisionExtensionSession` переносится между активными сценами группы: по умолчанию экземпляры пересоздаются, opt-in `RetainOnMapTransfer` сохраняет экземпляр, его RimVisionView и ресурсы. RimVisionView перепривязывает делегаты/камеру и своё поддерево активного вида; объекты слоёв остаются у исходных карт. StateChanged учитывает Map. Сессия остаётся единственным владельцем API-ресурсов и завершается до очистки сцен группы. MapView координирует передачу прежней сессии; нового механического состояния ему не добавлено.

`RimVisionPresentation` владеет слабо привязанными к Map локальными часами TickFraction: сброс при смене тика, остановка на паузе, нативная скорость SP/MP. Доля тика используется только в визуальных callbacks, не в SurfaceHeight или симуляции. `FPVManualBullet` запрашивает у пространственного провайдера физическую маску нативных вещей (`BlocksProjectile(Thing)`) отдельно от видимости; провайдер определяет физику своего заменённого объекта. `ConstructionActions` размещает обзорный проект на плоскости выбранной активной карты даже над пустотой. `WorldGeometry` владеет кэшем односторонних материалов нижней поверхности перекрытия; материалы освобождаются общим списком MapView.materials. Нижняя поверхность не видна сверху. Контракт не содержит названий MultiFloors; топология, маски проёмов и анимация его нативных Jobs принадлежат отдельному мосту.

## Пространственные изменения API 1.3 (исходники, без сборки/прогонов)

`RimVisionSpatialProvider` разделяет визуальный список CollectLayers и полную нативную группу CollectMaps; добавляет SurfaceDependsOn, DrawMountain, DrawRoofTop/RoofHeight, PickThing, CanShootAcross/BlocksProjectile. Данные этажей и симуляция остаются у адаптера/целевого мода. `SpatialMapRendering` владеет кэшем сцен группы, пошаговой подготовкой через MapView.BuildSteps и переключением ролей активной/дополнительной сцены. При активации подготовленной карты геометрия не пересобирается; прежняя сцена сохраняется, RenderTexture и PawnControl передаются новой. Unity-операции остаются на основном потоке. Локальные API-расширения закрываются/открываются при смене активной карты, а не становятся simulation state.

`WorldGeometry` остаётся владельцем крыш, гор и геометрии: природный потолок может не создавать гору; верхняя сторона перекрытия отделена от нижней; зависимые поверхности инвалидируются через существующие map notifications. Очередь перестройки чанков использует общий кадровый бюджет, подготовка новых слоёв имеет отдельный ограниченный бюджет. GroundShadow берёт текущую высоту слоя из shader global; PreviewSurface учитывает сторону нижней поверхности крыши. `RimVisionView.CreateSurfaceMaterial` выдаёт материал штатного shader во владение расширению, без передачи владения текстурой.

`FPVManualBullet` через собственную spatial-flight часть исполняет разрешённые межкарточные столкновения обычной ручной пули по нативным данным всех карт, с постоянным порядком кандидатов и применением Impact на карте попадания. Отдельной симуляции мира и урона из renderer нет; сохраняемое состояние полёта остаётся у существующего projectile. AI-бой, взрывы и произвольные сторонние снаряды этим не расширены.

`ConstructionActions` владеет обзорным размещением/протягиванием и очередью запросов; MapView только передаёт ввод и вызывает flush на прежней границе исполнения. Native Designator повторно проверяет выбранную Map, Def, stuff и клетку. Multiplayer имеет отдельный OverviewPlace с явной Map, вызываемый через bridge delegate; прежние пакеты команд не расширяются. `PreviewWindow` координирует отложенный выбор пешки/активацию сцены, HudPresentation и NextPawn читают нативную группу карт. Проверки и сборки этой итерации не выполнялись по просьбе пользователя.

API 1.2: `RimVisionControl` владеет упорядоченными регистрациями нативного управления; целевой мод остаётся владельцем связи Actor/Carrier, движения, Jobs, reservations и сохраняемого состояния. `PawnControlBridges` –  часть PawnControl, единственного владельца transient binding/lifecycle и ошибок callback; локальная MP-копия получает только snapshot без Attach/Detach. Выбранное нативное управление отключает пешие Harmony hooks через ForPawn, ручную смену Jobs/позиции/выносливости; при передаче удаляется только queued control Job RimVision. Native OrderJob/Cancel/SetCombat проходят прежнюю SP/MP границу, нулевой delta input не двигает носителя, ApplyClientPosition игнорирует его клиентский snapshot. Adapter сохраняет авторитетную позицию без пешего прогноза/tweener override. Save/load повторно разрешает binding с Restored, новых Scribe-ключей нет; выход сохраняет нативную очередь и добавляет прежние suspended Jobs в её конец. `RimVisionPresentation` владеет только регистрациями чистых локальных pose/visibility callbacks; PawnAppearance и ViewCamera применяют их в своих существующих алгоритмах без новых ресурсов. `RimVisionCombat` выбирает нативный валидатор/исполнитель; CombatActions вызывает его на прежних Fire/Melee границах, исключая двойное стандартное исполнение и пешие очереди burst для выбранного ranged provider. Частота/резервации/снаряды/урон остаются нативными, формат команд прежний. MapView координирует только прежний render loop. Контракты и пример –  Docs/API/NativeCompatibility.md и Example/Source/NativeRidingBridge.cs.

Пространственный API 1.1: `API.RimVisionSpatial` владеет реестром провайдеров топологии и отдельными межкарточными действиями; данные карт, связей этажей, проёмов и переходов остаются у целевого мода. `RimVisionSpatialProvider` задаёт elevation, CollectLayers/Revision, фильтры пола/крыши/вещей, дополнительную проходимость, визуальную высоту опоры и нативный Job перехода. PawnControl читает чистые ограничения в обоих путях движения и запускает переход только на стороне SP/синхронного исполнения; распознавание traversal Job разрешает прежние Harmony StartPath/PatherTick и следование цепочке playerForced Jobs. Новых сохраняемых полей контроллера нет; SurfaceHeight применяется только ViewCamera/PawnAppearance. `SpatialMapRendering` владеет дополнительными визуальными MapView и снимком Revision; эти контексты явно отделены флагом visualLayer от основного и simulation-only контекстов. Они повторно используют существующие WorldGeometry/ObjectPresentation/PawnAppearance/GameLighting, не захватывают ввод/слушатель, не создают свои погоду/небо/расширения, не тикают карты и не генерируют их. Сцены слоёв скрыты между проходами, каждая рисуется в заимствованный основной RenderTexture с общей глубиной и своим освещением/масками; renderer flags, targetTexture и shader globals восстанавливаются, stencil CommandBuffer принадлежит контексту слоя. При смене провайдера/Revision обновляются топология и прежние очереди чанков; при удалении карты/Dispose освобождается её сцена. MapView содержит только композицию, выбранный визуальный provider и существующий общий command context; в общей SP-очереди сохраняется порядок обычных и layer API-запросов. `ViewTargeting` владеет пространственным пикером с общим TryRaycastThing для прежнего наведения и нового API; чужая Map не подставляется в обычные команды/стрельбу. `SyncCommands.LayerAction` –  отдельная проверяемая команда с восемью аргументами, Map/Thing сериализуются штатным MP API; старый Rim3DCommand/Scribe не расширены. Пример отображения двух карт – Example/Source/TwoFloorPresentation.cs. Сам адаптер MultiFloors и межэтажный бой не реализованы.

Публичный C# API 1.0: `API.RimVisionApi` владеет process-wide регистрациями локальных расширений и действий с namespaced ID; реестры задают порядок priority/ordinal ID и не сохраняются. `RimVisionExtensionSession` владеет экземплярами только локального вида, уведомлениями о смене FPV/пешки и изоляцией ошибок/RNG локальных callback. Каждый `RimVisionView` владеет своим поддеревом сцены, явно переданными Mesh/Material/Texture и блокировками ввода; cleanup происходит после Dispose расширения и до общей очистки MapView. Заимствованные игровые ресурсы передавать во владение запрещено. MapView создаёт сессию после Build, вызывает обновление/рендер/HUD и освобождает её; новых mechanic algorithms ему не передано. Он сохраняет очередь локальных запросов SP как часть command context: исполнение после локальных callback с повторной проверкой пешки, вне восстановления RNG; при Dispose очередь очищается. MP использует прежний Work/Kind-пакет и проверку сессии через SyncCommands.Action; `RimVisionActionExecution` и обработчик регистрации повторно проверяют условия до нативной операции/OrderAction. Строительство меню остаётся в ActionMenus; обновление внешности/геометрии использует прежние OnPawnChanged/OnThingChanged. Simulation-only виды не создают сессий, ресурсов или HUD. `WorkMinigames` остаётся единственным владельцем фабрик миниигр: JobDef-регистрация приоритетнее замены категории; фабрика может получать Pawn, WindowSize публичен, награды проходят прежние WorkMinigameRewards/WorkProgressBonus. Старые публичные Register, Scribe-ключи и сетевой формат сохранены. Документация и пример аддона –  `Docs/API/`, включаются в пакет сборки как DeveloperAPI; инструментарий моделей не меняется.

Назначение цели миномёта доступно во время подхода и зарядки: UI проверяет клетку, исполнение –  текущий ManTurret, принадлежность орудия и нативное разрешение принудительной цели, без требования ManningPawn. Единственный владелец точки –  штатный ForcedTarget, который сохраняется до готовности орудия; отдельной ожидающей цели нет. MortarTargeting показывает подтверждённые координаты, подход/зарядку/блокировки и отсчёт по штатным burstCooldownTicksLeft/burstWarmupTicksLeft; сообщение о выстреле читает штатный lastShotTick. Уведомление о клике временное и не скрывает управление или состояние. Сетевые команды, Jobs и сохранения не меняются.

`NeighborMaps` –  GameComponent, координирующий подготовку восьми настоящих локальных карт одного surface-тайла мира в квадрате 3×3. `NeighborMapParent` –  сохраняемый владелец sourceMap и смещения; родители хранятся штатно в World.pocketMaps, полные карты –  в Game.Maps. Карты используют обычные surface TileInfo/температуру, поэтому не помечаются isPocketMap; pocketMapProperties генератора нужны для штатного удаления дочерних карт при удалении исходной. Результат генерации сохраняется штатным Scribe, повторное открытие 3D не генерирует карты заново. Генератор использует нативные шаги земли, скал, дорог, растений и животных без стартовых пешек/вещей сценария; seed содержимого дополняется локальным смещением. Только у NeighborMapParent пропускаются MapPreTick/MapPostTick/MapUpdate и регистрация объектов в TickManager; это приостанавливает окружение и объекты, сохраняя системный учёт времени Multiplayer. Переключатель Rim3DSettings локальный и по умолчанию выключен; отключение скрывает окружение и прекращает новые запросы, сохраняя данные карт. В Multiplayer хост запрашивает подготовку через host-only PrepareNeighborMaps → EnterSimulation → очередь long event с нативным сохранением RNG-контекста Multiplayer; клиентский renderer мир не изменяет. Переходов и бесшовного согласования краёв пока нет.

`NeighborMapRendering` владеет только локальными мешами, копиями материалов и дочерним объектом окружения. Читает сохранённые карты; объединяет землю, строит скалы по сетке 4×4 без внутренних граней и показывает не более одного дерева на блок обычными спрайтами. Заимствованные текстуры не уничтожает; собственные Unity-ресурсы освобождает при Dispose из MapView, simulation-only MapView renderer не создаёт. MapView только создаёт/обновляет/освобождает компонент; ViewCamera увеличивает дальнюю плоскость при включённом окружении. Полные данные соседей остаются в памяти и увеличивают сохранение; графическая оптимизация не является выгрузкой карт.

В ортографическом наведении миномёта шейдеры поверхностей, воды и эффектов отключают дистанционную дымку через штатный unity_OrthoParams, сохраняя туман войны. SpatialAudio использует AudioMapPosition у управляемой пешки для слушателя и расчёта дистанции Sustainer; высота артиллерийской камеры на звук не влияет. ПКМ отменяет назначенную цель через прежнюю Work-команду с Kind=MortarCancelTarget и штатный OrderAttack(LocalTargetInfo.Invalid), включая отмену во время перезарядки; Job и локальное наведение продолжаются. Escape и кнопка возвращают к пешке. Формат пакета, сохранения и жизненный цикл слушателя прежние.

`FPVWeaponFireState` хранит и сохраняет число ракет, выпущенных вручную из оружия с `Verb_ShootOneUse`. `CombatActions` учитывает только успешные выстрелы и уничтожает пусковую установку после `BurstShotCount` ракет через штатный `Thing.Destroy`; смена оружия и загрузка не сбрасывают расход. Для многоракетной одноразовой установки одно нажатие запускает оставшиеся ракеты через существующую очередь с интервалом `TicksBetweenBurstShots`, без выбора режима и нагрева. Одиночная игра использует прежний input cadence, Multiplayer –  FireControl и simulation ticks; новых сетевых команд нет.

`MortarTargeting` владеет локальным режимом изометрического наведения управляемого миномёта: фокусом/масштабом, подсветкой доступных клеток, выбором цели и подавлением повторного открытия после возврата к пешке в том же Job. Компонент создаёт визуальные ресурсы только при открытом режиме и сам освобождает меш, материал и объект при закрытии/DisposeFPV; simulation-only контекст ресурсов не создаёт. MapView координирует переход, блокировку обычного ввода и вызов камеры; ViewCamera применяет отдельную ортографическую позу, сохраняя FPV-ориентацию. Занятие миномёта идёт через прежний Interact → WorkActions → штатный ManTurret; PawnControl разрешает этому Job штатный путь к орудию, снарядам и топливу. Выбор цели проходит прежнюю команду Work с Kind=MortarTarget и повторную проверку пешки, Job, орудия, дальности и штатного CanHitTargetFrom перед OrderAttack. Снаряды, разброс, перезарядка и запрет огня остаются ванильными. Возврат закрывает только локальное наведение; движение/отмена прерывают работу прежним путём. Миниигры ManTurret не открывает. Сохраняемые поля и формат сетевого пакета не меняются.

`JobDriver_Rim3DSleep` завершает ручной отдых без активного PawnControl при 100% потребности отдыха или после штатного пробуждения. Под управлением пешка по-прежнему остаётся лежать до команды движения. Освобождение Multiplayer-сессии оставляет сон этому драйверу и не прерывает его немедленно; новых сохраняемых полей и сетевых команд нет.

`Rim3DSettings` хранит локальную настройку скрытия интерфейса для скриншотов; итоговое разрешение учитывает прежний редакторский переключатель. `PreviewWindow` скрывает интерфейс и использует весь экран для 3D, сохраняя доступ к меню по Escape. `WorkMinigameSession` закрывает только окно миниигры и блокирует его открытие на время скрытия, сохраняя текущую сессию. Игровое состояние и Multiplayer-команды не меняются.

`ZoneActions` владеет локальным переключателем цветной заливки зон и кэшем геометрии/материалов по ванильному цвету зоны. `ActionMenus` показывает кнопку «Области» под тремя переключателями билд-меню. Заливка использует существующие радиус 40 клеток и обновление раз в 0,5 с, учитывает цвета и изменения зон в сигнатуре; отключение контуров не отключает заливку. При инструменте домашней области используется её штатный цвет. Меши и материалы создаются через прежний registry MapView и освобождаются общим Dispose; симуляция, сохранения и Multiplayer-команды не меняются.

Непрерывные ручные сеансы: JobDriver_Rim3DBuild снимает таймер только своей рабочей стадии, сохраняя прежний finalizer переноса. ManualWorkSessions владеет правилами снятия таймеров чтения и пассивных развлечений у текущего playerForced задания активного PawnControl, а также ограничением CheckForJobOverride для ручного чтения/изготовления. Режим текущего нативного toil меняется до проверки его окончания в DriverTick; бильярд сохраняет этапы бросков, scoped-проверка убирает лишь общий deadline сеанса. Обычные задания и групповые занятия не меняются; завершение потребности/проверки доступности/принудительная отмена остаются у native Jobs. Сохраняемые имена JobDef/драйверов, Scribe-ключи и сетевые команды прежние; дополнительного состояния/ресурсов нет. WorkDurationEstimate использует ту же классификацию непрерывных развлечений при оценке времени.

Ручное исследование: WorkActions создаёт задание через штатный WorkGiver и только для обычного JobDefOf.Research выбирает Recovery_Rim3DResearch. JobDriver_Rim3DResearch наследует штатные toils, резервации, работу/обучение и fail conditions, меняя только завершение рабочей стадии с Delay на Never. Остановка остаётся штатной при завершении проекта, потере доступности или отмене управления; одного Job ID достаточно для сохранения локальной миниигры и подтверждений наград. Обычные колониальные задания и сторонние JobDef не меняются. JobDef присутствует в игровом моде и редакторских данных; тип драйвера/Def сохраняются обычным механизмом Scribe, а назначение в Multiplayer проходит прежний Work command → WorkActions → PawnControl.OrderAction.

`PlantSelectionFeedback` в Multiplayer-дополнении ограничивает штатным локальным пространством ID создание предупреждений `Command_SetPlantToGrow.WarnAsAppropriate`, которые Multiplayer выполняет только у автора команды. Прежнее значение `UniqueIdsPatch.useLocalIdsOverride` восстанавливается finalizer даже при исключении; выбор растения остаётся в штатной синхронизированной команде Multiplayer, одиночная игра не затрагивается.

`Rim3DSettings` хранит локальное предпочтение стрельбы при беге (по умолчанию выключено). В Multiplayer итоговое разрешение для ввода, выполнения стрельбы, прицеливания и позы оружия читается только из сохраняемого `HostMovementSettings` через `Rim3DMultiplayer`; хост обновляет его host-only командой `SetShootWhileRunning`, клиенты показывают значение хоста без редактирования. `CombatActions` сохраняет проверки на границе исполнения; `HeldThingPresentation` и `FirstPersonWeaponRenderer` отключают беговую позу оружия при включённом разрешении. Скорость, выносливость и состояние бега остаются у `PawnControl`.

Миниигры: `WorkMinigames` регистрирует фабрику игры и необязательную оценку длительности по JobDef; явная регистрация имеет приоритет, иначе для JobDriver_Mine и наследников создаётся `MiningMinigame`, для рубки дерева через JobDriver_PlantCut либо JobDriver_PlantHarvest с harvestTag=Wood и их наследников –  `WoodcuttingMinigame`, для JobDriver_Research и наследников –  `ResearchMinigame`, для остальных поддерживаемых рабочих действий –  наследник `ActivityMinigame`, иначе –  `SnakeMinigame`. Выбор использует JobDef и targetA; сбор плодов, срезание обычных растений и пней не получают игру лесоруба. `MiningMinigame` владеет локальной каменной поверхностью с рудными прожилками, точкой удара, трещинами, анимацией кирки/осколков, бегунком, ударами и очками: три попадания раскалывают участок, точный завершающий удар удваивает очки, промах снимает одно попадание; ввод и таймеры следуют паузе сессии, награды идут прежним путём. `WorkDurationEstimate` читает штатную работу/скорость/задержку текущего toil, для остальных действий с прогрессом оценивает остаток по первым изменениям полосы. `WorkMinigameSession` владеет исключительно локальной сессией, счётом и неприостанавливающим окном; MapView только вызывает обновление, рисует кнопку повторного открытия и освобождает сессию. Окно использует существующую блокировку внешнего ввода и не меняет Job. Смена работы, пешки или выход из FPV закрывает сессию; смена стадии того же Job сохраняет игру и счёт, движение временно приостанавливает миниигру. `WorkMinigameRewards` –  сохраняемый GameComponent с последней выданной наградой по пешке и job.loadID, проверяет текущие Job/toil и подтверждает награду только после продвижения работы через WorkProgressBonus. WorkProgressBonus владеет применением добавочного прогресса: ResearchPerformed для проекта, штатные рабочие поля/задержки остальных драйверов, Mining damage и уведомление о ремонте; завершение и результаты работы остаются у штатных механизмов. Дополнительного Learn нет; для нестандартной работы регистрация WorkMinigames принимает детерминированный обработчик бонуса. В Multiplayer запрос идёт отдельной командой с проверкой ControlSession, а HostMovementSettings хранит сохраняемое разрешение хоста, изменяемое только host-only командой. Локальные настройки миниигр/участия в наградах принадлежат Rim3DSettings; миниигры используют System.Random, не Verse.Rand. MiningMinigame лениво создаёт одну текстуру породы при первом рисовании, переиспользует её при смене точки/перезапуске и уничтожает в Dispose; окно и ресурсы по-прежнему освобождает WorkMinigameSession. Реальная добыча не зависит от миниигры; отдельной полосы её прогресса в окне нет.

WoodcuttingMinigame владеет локальными отметкой/стороной удара, ритмом, счётом и анимацией топора/щепок. Совпадение стороны и линии даёт 1 очко, точное попадание –  2; пропуск или промах не меняет обычную рубку. Пауза следует WorkMinigameSession, каждое очко проходит прежнюю очередь наград и WorkProgressBonus для PlantWork; новых ресурсов Unity, сохранений и сетевых форматов нет.

`WorkMinigameSession` также владеет локальной очередью неподтверждённых наград и ограничением частоты повторных запросов. Порог награды задаёт WorkMinigame.PointsPerReward: 5 по умолчанию, 1 у MiningMinigame, WoodcuttingMinigame, ResearchMinigame и ActivityMinigame; сессия применяет этот же порог при восстановлении счёта из номера награды. Подтверждением служит сохранённый номер в WorkMinigameRewards; повторная доставка не применяет бонус повторно. Локальный TinyBell играет один раз на награду (каждое очко тематических рабочих игр, каждые 5 очков змейки) с сохранением Verse.Rand, включая игру с отключённым бонусом; сетевые команды звук не воспроизводят.

WorkMinigameSession определяет доступ своего окна к вводу через штатный WindowStack.GetsInput; это одна общая проверка для паузы миниигры и разрешения хоткея ускорения. Служебные оверлеи без захвата ввода не удерживают паузу после закрытия события. MapView разрешает назначенный хоткей через прежний ViewInput/ToggleActionAcceleration; блокировки движения, прочих действий и сторонних диалогов сохраняются. Отдельного состояния скорости миниигра не хранит.

План этапов 1–6 выполнен в коде на ветке `refactor`. Это карта текущего разделения ответственности, а не подтверждение ручной проверки. Реестры каждого переноса находятся в [архиве рефакторинга](../Archive/Refactoring/README.md); заключительная сверка –  в [Stage-06-Audit.md](../Archive/Refactoring/Stage-06-Audit.md).

Настройка компаса принадлежит `Rim3DSettings`; `HudPresentation` и ввод меток читают итоговое разрешение. `HudPresentation` проецирует только пользовательские метки в 3D-вид и определяет метку под прицелом для подсказки и существующего окна редактирования; использует исходный список меток без отдельного кэша и новых Unity-ресурсов. Автоматические метки остаются только на компасе. В Multiplayer `HostMovementSettings` хранит сохраняемый запрет хоста для всей сессии (включая подключающихся игроков), обновляемый хостом через `SyncCommands.SetCompassDisabled`; `Rim3DMultiplayer` предоставляет его локальному интерфейсу.

Блокировка пешек клиентов: `Rim3DSettings` хранит предпочтение хоста; `HostMovementSettings` владеет синхронизированным флагом, именем хоста и сохраняемой привязкой игроков к пешкам. `ControlSessions.Claim` проверяет и регистрирует привязку; снятие управления её не удаляет. `MapView` применяет ограничения переходов, `PreviewWindow` –  закрытия, `Rim3DPreview` –  сохранения 3D и карты; `Immersion` завершает падение свободной камерой, `HudPresentation` отображает статус. Команда `SetPawnLock` зарегистрирована как host-only; выключение очищает привязки.

`WorldOverlays` владеет локальными переключателями плодородности, электросетей и красоты, ограниченными областью возле управляемой пешки (12 клеток; для красоты –  ванильная область восприятия). `WorldOverlays` также включает ближайшие электросети на время размещения постройки с CompPower и плодородность при выбранном инструменте зоны посевов, не меняя ручные переключатели. `ActionMenus` рисует переключатели под билд-меню; `HudPresentation` выводит плодородность целевой клетки и параметры текущей комнаты, а WorldOverlays –  подписи красоты с проверкой видимости. Обновление мешей ограничено локальной областью и интервалом 0,5 с, перемещение пешки обновляет область сразу. Меши и материалы зарегистрированы в общих коллекциях MapView и освобождаются его Dispose; симуляционные контексты их не создают. PlaySettings, сохранение и Multiplayer-команды не изменяются.

## Композиция и состояние

`SkyRenderer` определяет космическую карту только при активной Odyssey и ванильном `BiomeDef.inVacuum`; владеет параметрами орбитального фона PreviewSky, ориентацией относительно клетки мира и локальным движением облаков по MapTicks в Multiplayer. Поверхность планеты процедурная, облачный слой заимствован из ванильного World/CloudMap и не уничтожается при Dispose. Собственных ресурсов сверх прежнего шума неба нет. BiomeLighting задаёт космическое освещение, WeatherRendering отключает наружный атмосферный туман и осадки; WorldGeometry учитывает TerrainDef.dontRender при первичной сборке, обновлении чанков и переходах поверхностей. Обычные карты используют прежний фон; симуляция, сохранения и Multiplayer-команды не меняются.

`CombatEffectsRenderer` считает начало и возраст броска подковы в тиках одной карты; Multiplayer-адаптер предоставляет штатный `AsyncTimeComp.mapTicks` через `Rim3DMultiplayer.MapTicks`, без копии счётчика. При `PawnControl.AutomaticActionPath` локальное представление Multiplayer использует штатный `Pawn.DrawPos` для камеры и не переопределяет `PawnTweener.TweenedPos`; симуляционная позиция и синхронизированные команды остаются прежними.

`ShotAudio` в Multiplayer-дополнении владеет локальной ограниченной очередью звуков ручных выстрелов: синхронизированная стрельба передаёт исходные SoundDef и позицию через `Rim3DMultiplayer.ShotSound`, а GameComponentUpdate воспроизводит звук вне сетевой команды с сохранением Rand. Очередь принадлежит текущей игре, не сохраняется; звуки другой карты и устаревшие события отбрасываются. Стандартная отрисовка и дистанция слышимости остаются у звуковой системы игры и SpatialAudioListener.

`DebugActionIdentity` в Multiplayer-дополнении задаёт независимые от языка сетевые идентификаторы пунктов dev-меню газа и взрывов до сортировки по локализованным названиям. Метаданные привязаны к узлам через ConditionalWeakTable и освобождаются вместе с ними; `DebugActionSyncLabel` использует их только при построении и поиске сетевого пути Multiplayer, сохраняя локализованные подписи интерфейса и штатное выполнение команд.

Точные перемещённые private поля перечислены в реестрах соответствующих этапов. Если поле читается другой подсистемой, cleanup или совместимостью, оно сохраняется у MapView: копии/двусторонняя синхронизация не вводились. Владение handle/cache не означает повторное уничтожение Unity resource: общего владельца `meshes`, `materials`, `pawnTextures`, `root`, `Target` переносы не меняют.

Закрытые вложенные компоненты 4–6 держат readonly `_view`. Это сознательная зависимость от существующего приватного контекста: сохраняет getters, callbacks, порядок вызовов и Harmony boundaries без массового открытия полей/снимков состояния. Компоненты не являются полностью независимыми сервисами. Дальнейшее сужение этих контрактов потребует отдельной задачи с игровыми проверками.

`WorldGeometry` строит боковые грани пола толщиной 0,35 клетки на границах с пустотой и у края карты, без нижней поверхности и внутренних граней. Кэш боковых материалов принадлежит WorldGeometry; материалы зарегистрированы в MapView.materials и освобождаются общей очисткой, меши используют прежний lifecycle чанков. Проверка соседей читает terrain/fog и маску DrawFloor напрямую, независимо от очищаемого scratch; изменения обновляются прежними уведомлениями соседних чанков и пространственной топологии.

## Что сознательно осталось в MapView

`WorldGeometry` также владеет сохранёнными поверхностями стен для следов повреждений, отдельными мешами этих следов и очередью их обновления по чанкам. `BuildingsDamage` обновляет только этот слой; полная пересборка чанка заново собирает поверхности и слой повреждений. Меши слоя зарегистрированы в общем registry MapView: при локальном обновлении их освобождает WorldGeometry, при полной пересборке –  существующая очистка чанка, при Dispose –  общая очистка ресурсов MapView; собственные ссылки и очередь очищаются через ClearWallDamage.

- Создание сцены, Build/Render/Dispose, общий registry ресурсов, shader globals, map events и последовательность UpdateCamera.
- Переходы overview/FPV/event/sleep/fall, выбор управляемой пешки, блокировки ввода, native Targeter и согласование UI с игровыми действиями.
- Общий контекст команды/цели/строительства, simulation entry points и сохранение этого контекста.
- PawnAppearance вместе с capture/cache/raycast и полями `pawnViews`/`pawnCards`: тесная цепочка с Facial Animation и исходными полями Harmony injection сохранена целиком.
- Известные reflection hooks и прежние методы-посредники. Внутренние потребители и delegates продолжают обращаться к этим точкам, поэтому их удаление не является безопасной косметической операцией.
- Чистые static geometry/helpers, JobDriver/Def/сохраняемые типы, enum и существующие вложенные designators.

Из 402 обычных instance methods MapView 323 являются выражениями делегирования компонентам. Число строк не использовалось как критерий завершения; `partial` сохранён.

## Автоматические LOD моделей

`Rim3DModelLodBuild` создаёт два упрощённых варианта XML-моделей только в staging при сборке мода; исходные модели не изменяются. `OptionalModelLibrary` загружает встроенные `autoLods`, пустой уровень повторно использует предыдущий вариант, повреждённый уровень заменяется исходной моделью. Исходная модель остаётся владельцем геометрии поверхностей, anchors и связей.

`ObjectPresentation` владеет дистанционным выбором детализации, уровнями статических чанков и кэшем материалов дальних 2D-карточек. Раз в четверть секунды ставит изменившиеся чанки в существующую очередь WorldGeometry; пересборка сохраняет прежний бюджет и освобождение мешей. Материалы карточек зарегистрированы в общем registry MapView. `PawnAppearance.PawnView` хранит применённый уровень животного и использует прежнюю очистку/создание геометрии и штатное 2D-представление. Предметы в руках и анимированные турели/ветряки сохраняют исходную детализацию. `Rim3DSettings` владеет локальными настройками включения LOD/2D и дистанциями; игровое состояние, сохранения мира и Multiplayer-команды не меняются.

## Переназначение клавиш

`Rim3DSettings` владеет двумя локальными назначениями на действие, их сохранением, сбросом и окном захвата клавиши во вкладке управления. Версия назначений в настройках инвалидирует локальный кэш размеров подсказок `HudPresentation`. `ViewBindings` задаёт действия и значения по умолчанию, читает назначения для Unity Input и GUI-событий и подставляет их в подсказки. Escape и кнопки мыши сохраняют прежние функции. Компоненты действий используют назначения до существующих границ синхронизации; сетевые команды и сохранения мира не меняются.

ResearchMinigame владеет локальной решаемой схемой 4×4, поворотами узлов, обходом питания, подключёнными выходами и счётом. Фиксация 1–2 выходов даёт 1–2 очка, трёх –  4, затем создаёт новую схему. Случайность локальна, ресурсов Unity нет. WorkProgressBonus ограничивает исследовательский бонус 600 simulation ticks труда текущей пешки и 1% проекта на награду; WorkMinigameRewards владеет сохраняемым расходом бонусных ticks по текущим Job/toil (researchRewardToilIndex/researchRewardTicks), ограничивает выдачу половиной debugTicksSpentThisToil и подтверждает её только после продвижения исследования. Ожидающие лимита награды остаются в очереди WorkMinigameSession. Прежние Scribe-ключи и сетевой формат не меняются, новые ключи имеют безопасные значения по умолчанию; после сброса счётчика toil лимит может консервативно задержать выдачу. MapView не получает новой логики.
Рабочие миниигры: ActivityMinigame владеет общей локальной паузой, счётом, короткой блокировкой ввода и оформлением; BuildingMinigame, RepairMinigame, CraftingMinigame, SowingMinigame, HarvestMinigame, DismantlingMinigame, SmoothingMinigame и BandagingMinigame –  алгоритмами своих этапов и жестов. WorkMinigames выбирает их по JobDriver (включая наследников) и исключает Bill_Medical из изготовления; единый IsWoodcutting классифицирует древесину для фабрики и правил бонуса. Регистрации фабрик остаются приоритетными. Поля этапов и случайность не сохраняются, System.Random не влияет на симуляцию, ресурсов Unity и подписок нет. Пауза отменяет активные жесты; сглаживание обрабатывается один раз на кадр.

WorkProgressBonus владеет ограничением наград новых рабочих игр: одна единица за завершённый этап, до 5% операции и не больше эквивалента 600 simulation ticks штатного труда. Скорости/поля берутся из существующих native Jobs: ConstructionSpeed и stuff для Frame, RecipeDef для DoBill (без изменения медицинских операций), PlantWork/PlantSow, Repair, AffectFloor, SmoothWall и RemoveBuilding; лечение меняет только оставшуюся задержку TendPatient. Общий лимит исследования +50% не расширяется на другие работы. Добыча жил/деревьев сохраняет 5% за очко, змейка –  за пять. Ошибки миниигры не меняют мир; Apply остаётся на существующей синхронизированной границе. Save/load, сетевые команды, владельцы Job/резерваций/качества и cleanup не меняются. MapView остаётся координатором без новых алгоритмов и состояния.
Развлекательные миниигры: WorkMinigames отдельно выбирает ChessMinigame по Play_Chess и HorseshoesMinigame по JobDriver_PlayHorseshoes/наследникам, сохраняя приоритет регистраций. WorkMinigame задаёт WindowSize (прежние 430×470 по умолчанию, у шахмат 520×600 для читаемой доски); MinigameWindow читает размер при открытии, сессия закрывает окно до освобождения игры. Общий JobDriver_SitFacingBuilding не используется для выбора шахмат, поэтому GameOfUr и другие развлечения не затрагиваются; PlayHoopstone имеет отдельный драйвер. ChessMinigame владеет ограниченной генерацией решаемых коневых вилок 8×8, положением фигур, проверкой ходов и ошибками. HorseshoesMinigame владеет направлением, силой, локальным ветром, полётом и оценкой приземления. ActivityMinigame сохраняет общую паузу/счёт/задержки и предоставляет RewardHint для различения рабочих и развлекательных подсказок. Результат 1–2 очка идёт через прежний WorkMinigameSession → WorkMinigameRewards → WorkProgressBonus → GainJoy; штатные joy Jobs, симуляция, обучение и управление участниками не меняются. Состояние локальное, System.Random, новых Unity-ресурсов/подписок/сохраняемых полей/сетевых команд нет.

Непрерывный посев зоны: WorkActions остаётся единственным владельцем локальной зоны/пешки/исходной клетки/ID запроса. Первый Interact запускает сеанс, отпускание кнопки его не сбрасывает; следующий штатный Sow ищется после завершения предыдущего через прежние Work/Sow и валидацию WorkGiver, резерваций, пути, погоды и зоны. TrySow возвращает результат существующей границе исполнения, SowingResult/NotifySowingResult очищают только локальный запрос без новых игровых мутаций. В Multiplayer Adapter направляет уведомление локальному владельцу по прежнему образцу GrowingZoneCreated; новых сериализуемых полей/команд нет. DisposeFPV снимает сеанс через прежний ResetSowingInput, сохраняя остальные cleanup-операции.

WorkMinigameSession получает зону как заимствованный идентификатор сеанса от WorkActions и сохраняет игру/окно/общий счёт между Sow Jobs одной зоны и пешки. В промежутке между Jobs и при движении игра приостанавливается. Смещение _rewardPointBase отделяет общий отображаемый счёт от номеров наград текущего Job. При смене Sow сначала читается подтверждение старого Job; только неподтверждённая очередь перенумеровывается для нового Job без повторного звука. Старые команды больше не могут пройти проверку Job ID. Завершение сеанса, смена пешки/зоны/действия и выход из FPV очищают эту локальную связку. WorkDurationEstimate оценивает порог 5 секунд по текущей и ещё пустым клеткам всей зоны, не создавая Jobs и не меняя растения. HasWindowInput использует общий WindowStack.GetsInput; FPVActions разрешает продолжать посев под собственным окном, остальные блокировки сохраняются. MapView только передаёт зону, сведения о доступе окна к вводу и уведомление результата.

`HudPresentation` owns the F1 controls help window and its contextual hint snapshot. The window highlights hints available immediately before opening and lists the remaining contextual controls and current bindings. `PreviewWindow` renders the full-height view and a lower-left help button; the saved BottomControls setting controls only this button. InputPatch routes F1 before gameplay input. The help window uses the native window input barrier and closes when its owning view is removed; no simulation or Multiplayer commands change.

Миномёт: ПКМ читается в UpdateMortarTargeting тем же Unity Input, что и движение камеры; GUI только поглощает событие. Синхронизированная MortarCancelTarget включает штатный holdFire, сбрасывает ForcedTarget/CurrentTarget и незавершённый Verb; новая MortarTarget снимает holdFire перед OrderAttack. Новых сохраняемых полей/сетевых форматов нет. MortarTargeting владеет отметками орудия/пешки, компасом, контурами min/max дальности и вторым красным материалом недоступных клеток; оба материала и меш освобождаются в Close. Локальный счётчик Shell обновляется раз в секунду и использует штатный радиус JobDriver_ManTurret, allowedShellsSettings, CanReserve/CanReserveStack и путь от миномёта; следующий тип определяет штатный FindAmmoForTurret с сохранением Rand. Интерфейс не резервирует боеприпасы. CombatEffectsRenderer отображает flyOverhead-снаряды параболой к штатному destination, сохраняя горизонтальную траекторию и время полёта симуляции; размер тела/следа учитывает ортографический масштаб. След использует прежний материал эффектов и cleanup ShotVisual.Trail, тело –  прежний Body. Simulation-only контексты новых ресурсов не создают.

Сглаживание миномётных снарядов принадлежит CombatEffectsRenderer: дробная часть тика карты вычисляется локально по времени кадра и текущей скорости симуляции; между нативными обновлениями flyOverhead положение на дуге прогнозируется максимум на UpdateRateTicks. Тело и след используют один progress, остановка полёта читается из штатного Projectile.landed. На паузе дробная часть не растёт; Multiplayer использует MapTicks и существующий источник скорости карты. Локальные часы сбрасываются в DisposeExplosiveEffects. Симуляция снаряда, сохранения, сетевые команды и отрисовка обычных гранат не меняются.

Переход управляемой пешки между картами: Rim3DPreview следует за картой пешки, PreviewWindow пересоздаёт визуальный MapView, а MapView передаёт существующий PawnControl новому виду до освобождения старого. Контроллер сохраняет задание и исходное состояние пешки; NotifyMapTransfer сбрасывает только координаты и локальный подход старой карты. Во время despawn ввод приостановлен. В Multiplayer ControlSessions переносит ту же сессию при штатном Pawn.SpawnSetup (кроме загрузки), сохраняя owner/token и контроллер; MapComponentTick страхует перенос. Старый simulation-only контекст отбрасывается без Dispose контроллера, новый создаётся лениво. Adapter сбрасывает локальный прогноз позиции при смене карты. Scribe-ключи и сетевой формат прежние.

Настройки миниигр: Rim3DSettings владеет отдельной вкладкой, локальным набором отключённых игр и предпочтениями наград/множителей по WorkMinigameKind. WorkMinigames задаёт общую классификацию для фабрики, локального выключения и бонусов. Явные регистрации сохраняют приоритет фабрики и используют группу своего Job; отключённая игра не заменяется змейкой. В Multiplayer HostMovementSettings –  авторитетный сохраняемый владелец разрешения наград и множителей. SetMinigameRewards/SetMinigameMultiplier зарегистрированы host-only, Adapter предоставляет значения через Rim3DMultiplayer; клиентские переключатели игр не синхронизируются и не влияют на других игроков. Локальное предпочтение наград клиента не участвует в отправке/применении бонуса. WorkProgressBonus читает множитель на прежней границе исполнения и масштабирует базовую награду и её лимиты; ×1 сохраняет прежнее поведение, ×0 не выдаёт наград. Новые коллекции по умолчанию пустые: все игры включены, множители ×1. Новые Unity-ресурсы, сохраняемые Job-поля и форматы прежних команд не вводятся.

Приседание и прицеливание игроков в Multiplayer: PawnAppearance.PawnView владеет локальным сглаживанием опускания тела на 0.57 из существующего PawnControl.Sneaking; HeldThingPresentation использует тот же сдвиг для предметов и хранит сглаживание позы прицела в HeldCard. ControlSession владеет сохраняемым WeaponAiming; отдельная команда WeaponAim проверяет owner/token, Adapter передаёт штатное условие прицела MapView и читает состояние с проверкой срока ввода. При смене карты флаг сбрасывается, старые сохранения получают false. Форматы прежних команд и игровые механики не меняются; визуальные blend не сохраняются, ресурсов и подписок не добавлено.
Попадания по приседающим в Multiplayer: PawnControl задаёт единое условие IsCrouching и CrouchDepth для представления и ручной баллистики. FPVManualBullet уменьшает стоячий объём на синхронизированное опускание, ограничивая его полом, а часть тела определяет относительно смещённого полного силуэта. Обычный и пространственный полёт используют один CollisionHeight. Для выбранной цели HeldThingPresentation/MapView передаёт прежнюю высоту силуэта без локального сглаженного приседания; текущее приседание читается из авторитетного контроллера при полёте и попадании для любой пешки. Новых состояний, Scribe-ключей и сетевых полей нет; одиночный режим, лежачие пешки и штатное применение урона сохранены.
