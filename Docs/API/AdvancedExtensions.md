# Расширения API 1.6

API 1.6 дополняет [основное руководство](README.md) и [контракты 1.5](PresentationAndInput.md).

## Ввод

Прежний RegisterBinding и его клавиатурные ограничения сохранены. Новый RegisterGesture принимает две RimVisionInputGesture: KeyCode и флаги Shift/Control/Alt. Разрешены клавиатура, Mouse0–Mouse6 и именованные Unity KeyCode кнопок джойстика; Escape/F1/F11 зарезервированы. Модификаторы проверяются включительно: дополнительные нажатые модификаторы не запрещают жест. Коллизии разрешаются priority/ID и возвращаемым bool обработчика. Поглощается основная клавиша/кнопка; сами модификаторы сохраняют обычное действие.

```csharp
RimVisionInput.RegisterGesture("author.mod:action", "My action",
    new RimVisionInputGesture(KeyCode.R, RimVisionInputModifiers.Control), default,
    RimVisionInputChannels.Interaction, RimVisionInputContext.Pawn,
    state => state.CanControl,
    (state, phase) => {
        if (phase == RimVisionInputPhase.Pressed)
            RimVisionApi.SubmitAction("author.mod:registered-action", state.AimedThing, state.AimedCell);
        return true;
    });
```

Контексты Overview, Pawn, NativeControl, Cursor, Menu объединяются через OR. NativeControl дополнительно помечает режим Pawn; Cursor означает освобождённый курсор/обзор. Menu относится к внутренним меню RimVision. Контексты не обходят блокировки, текстовый ввод, внешние окна или потерю фокуса. В специальных режимах перехода, падения и миномёта пользовательские привязки отменяются. После отмены удерживаемого жеста нужно отпустить кнопку перед новым нажатием; аналоговая ось может возобновиться при возвращении доступности.

SetGesture(id, secondary, gesture) переназначает новую привязку и сохраняет ModSettings. Окно управления RimVision позволяет захватывать сочетания клавиш и кнопки мыши; для мыши нажмите в области приглашения. BindingLabel включает модификаторы. Старые назначения и их Scribe-ключи сохранены; модификаторы имеют отдельные ключи и входят в общий сброс.

RegisterAxis принимает источник MouseX/MouseY, ScrollX/ScrollY, UnityAxis либо Custom, канал, контекст, предикат доступности и обработчик RimVisionAxisInput. У UnityAxis обязательно имя уже существующей оси Unity. API не создаёт новые InputManager axes и не подключает драйвер устройства. Custom принимает read: Func<RimVisionViewState, float>, поэтому мост геймпада может передавать собственные аналоговые значения без зависимости от встроенного списка осей.

AxisInput содержит Value, Phase и DeltaSeconds. Переход 0→значение даёт Pressed, дальнейшие ненулевые значения –  Held, возврат к нулю –  Released, потеря доступности –  Cancelled с Value=0. Мёртвая зона и инверсия задаются при регистрации и настраиваются в управлении RimVision. Порог мёртвой зоны обнуляет малые значения; остальные значения не перенормируются. В mouse axes используются существующие оси RimVision; отсутствие Unity axis отключает эту привязку для вида и отражается в диагностике. Источник Custom идентифицируется ID привязки; независимые Custom ID не поглощают друг друга. Порядок определяется отдельно внутри реестров осей и клавиш; оси обрабатываются первыми.

```csharp
RimVisionInput.RegisterAxis("author.mod:forward", "Forward", RimVisionAxisSource.Custom,
    RimVisionInputChannels.Movement, RimVisionInputContext.Pawn,
    state => state.CanControl,
    (state, input) => RimVisionInput.SetControlAxis(RimVisionControlAxis.MoveZ, input.Value),
    read: ReadMyGamepadForward);
```

SetControlAxis разрешён только из callbacks привязок/осей во время их обработки. Он изменяет локальный ввод текущего кадра, а не мир. MoveX/MoveZ/MoveY суммируются с обычным вводом и ограничиваются [-1,1]. LookYaw/LookPitch задают градусы в секунду; положительный LookPitch наклоняет вниз. Zoom задаёт добавку к колесу. Значения очищаются перед следующим опросом. Их применяют прежние ViewInput/PawnControl и Multiplayer-граница; вертикальная ось влияет только на поддерживающее её нативное управление. Не вызывайте Controller.Move или нативные изменения мира из обработчика ввода.

Поглощённые mouse axes подавляют соответствующую составляющую штатного обзора/зума, кнопки –  обычные игровые нажатия. Это не перехват произвольного IMGUI сторонних окон. Одно лишь получение данных оси не должно поглощать её: верните false, если наблюдаете ввод.

## Камера

RimVisionCameraProvider получил Activated(context), Deactivated(context, reason) и TransitionSeconds. Значение перехода по умолчанию 0 сохраняет поведение старых провайдеров. Обработчики выполняются локально с восстановлением Rand. Контекст содержит ViewId для разделения состояния разных видов. Причины отключения: Replaced, Unavailable, ViewClosed, MapChanged, CallbackFailed. Частично начатая активация также проходит cleanup. После ошибки провайдер отключается для текущего вида; новый вид может разрешить его заново.

ViewCamera сохраняет неактивные дистанции primary-провайдеров и штатной камеры. При смене владельца дистанция восстанавливается до вычисления позы; собственная повторная копия активной дистанции аддону не нужна. Эти локальные профили не сериализуются. Переход интерполирует позицию, поворот и совместимый FOV; проекция, ограничения ввода, видимость и origin прицеливания сразу соответствуют новому кадру.

CollisionRadius расширяет проверку препятствий до девяти параллельных лучей в поперечном сечении камеры. Ноль сохраняет прежний центральный луч. ThirdPerson устанавливает радиус .2. Это выборка визуальной геометрии существующим пикером, а не непрерывный физический sphere cast: тонкие препятствия между лучами могут быть пропущены. Радиус и ObstaclePadding выбираются под конкретную камеру. После интерполяции сохраняется ограничение отступа.

Свободный обзор отделяется через MovementYaw от визуальной ориентации; смена плеча задаётся знаком shoulderOffset.x. Нативные ограничения движения и разрешение атаки остаются у прежних компонентов.

## Фактическое выполнение Jobs

Прежние Status/Completed/ActionCompleted по-прежнему описывают принятие и исполнение запроса команды. Succeeded у RegisterJobAction не означает завершённый ремонт или иную работу.

У RimVisionActionRequest добавлены JobStatus и JobId. Для SubmitAction/SubmitLayerAction, исполняющих CreateJob, доступен отдельный поток RimVisionExtension.JobChanged(view, notification):

| JobStatus | Значение |
| --- | --- |
| None | Запрос не создал отслеживаемый Job. |
| Queued | Job передан прежнему контроллеру. |
| Running | Нативный JobDriver начал работу. |
| Succeeded | Нативное завершение с JobCondition.Succeeded. |
| Failed | Incompletable, Errored или ErroredPather. |
| Interrupted | Иное завершение/снятие из очереди. |
| Rejected | Контроллер не принял Job. |
| Detached | Вид больше не наблюдает за работой; это не отмена Job. |

Уведомление содержит RequestId, ActionId, Pawn, JobId, JobDef и нативный Condition. События доставляются локальным расширениям на прежнем update/flush с восстановлением Rand, не внутри JobDriver. Короткий Job может завершиться в том же вызове, в котором был принят. Получение события не является разрешением менять мир из callback: отправляйте следующую зарегистрированную команду.

Наблюдение использует Notify_Starting/Cleanup и возврат Job в нативный пул. Механика работы, reservations, очередь и JobCondition не заменяются. Для нативного владельца без стандартного JobDriver доступны RimVisionJobs.NotifyStarted(actor, job) и NotifyEnded(actor, job, condition), вызываемые на авторитетной границе. Не посылайте эти события из renderer. Нельзя объявлять Succeeded на основании исчезновения CurJob.

В Multiplayer результаты передаются только наблюдающему локальному владельцу через существующий owner/token контекст исполнения. Обычные native ticks учитываются отдельно от локального интерфейса. Трекеры очищаются также при нативном ClearAllMapsAndWorld. Они transient и не имеют Scribe-ключей: после загрузки старое наблюдение не восстанавливается. Сохранённые Jobs продолжают нативную работу. Внешний мод остаётся владельцем своего сохраняемого состояния.

## Взаимодействия

RimVisionInteractions.RegisterProvider выбирает первый подходящий Evaluate(state, ref interaction). Исходный interaction содержит AimedThing/AimedCell и OverrideDefault=true. Провайдер задаёт существующий ActionId, Label, Description, необязательную заимствованную Icon, HoldSeconds, TargetMap/Target/Cell/Value. HoldSeconds ограничен 0–60.

Доступность и причина отказа берутся у прежнего зарегистрированного действия. При завершении удержания отправляется SubmitAction/SubmitLayerAction; в SP/MP исполнитель повторно валидирует команду. Удержание –  только локальный жест подтверждения. Оно не заменяет нативный warmup, reservations или синхронную проверку игрового времени. Отмена, потеря цели/провайдера/фокуса, блокировка, пауза и смена вида снимают незавершённое удержание. После потери ввода требуется новое нажатие.

OverrideDefault=true обрабатывает E для выбранного взаимодействия, включая недоступное, чтобы запрет не запускал другое ванильное действие. false оставляет штатный E и показывает информацию; действие можно вызвать отдельной привязкой или из его обычного меню. Активные инструменты, выбор целей и меню сохраняют свои режимы. Эти провайдеры не подменяют всю систему контекстных меню.

RimVisionInteractions.Current содержит Interaction, Available, Reason, Progress. Новый HUD-элемент Interaction отображает подсказку, иконку, tooltip и прогресс. Его можно скрыть/заменить прежним RimVisionHudProvider. При выключенном HUD само взаимодействие остаётся доступным.

## Модели объектов

RimVisionModels.RegisterProvider выбирает модель Thing по priority/ID. Провайдер задаёт Handles, Create(context), Update(context, ref frame), Dispose(context); HideDefault по умолчанию true. Это отдельный контракт визуального представления, не изменение ThingDef, размеров клетки или физики.

RimVisionModelContext содержит Thing, Map, Observer, Root, DefaultPose, IsOpen. В Create заполняйте предоставленный Root; не уничтожайте и не переподчиняйте его. Core назначает слой созданной иерархии после Create. Дочерним объектам, созданным позднее, назначайте Root.layer сами. Контракт работает в активной и дополнительных визуальных сценах карт; simulation-only виды модели не создают.

OwnResource принимает только собственные Mesh/Material/Texture. CreateSurfaceMaterial выдаёт собственный материал штатного shader, не забирая текстуру во владение. Заимствованные игровые ресурсы не передавайте в OwnResource. Dispose вызывается перед уничтожением Root и ресурсов, в том числе после частичной ошибки Create. Освобождайте здесь свои подписки и внешние ресурсы; ресурсы, переданные Core, повторно не уничтожайте.

RimVisionModelFrame содержит Pose, Scale, Visible, DrawDefault и необязательные PickingBounds в локальных координатах модели. Поза/масштаб каждый кадр начинаются со штатного представления; DrawDefault и PickingBounds сохраняют последнее значение до явного изменения. Visibility не обходит карту, туман войны и исходные ограничения показа персонажа. Для показа тела в FPV используйте прежний camera/presentation контракт.

PickingBounds участвуют в визуальном пикере и проверках камеры. При заданных bounds промах не подменяется попаданием в старый спрайт. Без них остаётся прежняя геометрия выбора цели. Это не hitbox снаряда и не разрешение на попадание/урон. Произвольные новые projectile renderers и скелетная анимация по-прежнему реализуются нативным владельцем модели.

Смена состава регистраций пересоздаёт модели и инвалидирует только затронутое представление. Изменения native Thing читаются в Update; для новой классификации Handles используйте снятие/повторную регистрацию. Ошибка экземпляра возвращает штатное представление после его визуальной перестройки и отражается в диагностике. Callback не должен менять мир.

## Анимационные события

RimVisionExtension.AnimationEvent получает RimVisionAnimationEvent: Pawn, Item, Kind, Phase, Progress, Magnitude, Tick. Kind: Equip, Reload, Ability, Damage; Phase: Begin, Progress, Impact, Complete, Cancelled.

Core сообщает завершение смены оружия по снимкам и положительный фактический урон через Pawn.PostApplyDamage. События скрытых чужих пешек не поступают локальному виду. Reload/Ability и их прогресс явно сообщает интеграция через RimVisionPresentation.NotifyAnimation. API не угадывает чужую перезарядку по имени Job. Уведомление не выполняет саму перезарядку, не списывает боеприпасы и не создаёт способность. Для сохранения и игровых изменений остаётся нативный владелец.

Старые PresentationEvent/Shot/Melee сохранены. Не посылайте одно и то же событие одновременно из нативного исполнения и renderer. В Multiplayer авторитетные уведомления доставляются локальным слушателям без нового игрового пакета; эффект не синхронизирует произвольные поля аддона.

## Эффекты и звук

view.CreateEffect(map, pose, duration, update, pauseWithGame=true) создаёт принадлежащий виду локальный объект на отображаемой карте. CreatePawnEffect привязывает его к прежней точке крепления. Возвращается IDisposable RimVisionEffect с Root/IsAlive. Ноль duration означает жизнь до Dispose/закрытия вида; положительное значение задаёт секунды. Эффекты ограничены 512 на расширение. Ресурсы отдельного эффекта передавайте в effect.OwnResource или создавайте через effect.CreateSurfaceMaterial: они освобождаются вместе с эффектом. Ресурсы, совместно используемые всем расширением, принадлежат прежнему view.OwnResource. Один ресурс нельзя передавать обоим владельцам.

Update получает Root и RimVisionEffectContext с Elapsed, Duration, Progress, State, Map и Paused исходной карты эффекта. При pauseWithGame время на паузе не накапливается. Стационарный эффект скрывается в тумане войны, привязанный наследует видимость крепления. Смена карты не переносит стационарный эффект с его карты; при удалении карты эффект освобождается. При закрытии расширения очищаются все его эффекты, включая удержанные объекты при RetainOnMapTransfer.

view.PlaySound(soundDef, map, cell) использует нативный одноразовый звук. StartSound возвращает IDisposable RimVisionSound для нативного Sustainer с Maintain/End. Звуки принадлежат расширению, ограничены 128, останавливаются при закрытии/удалении карты/скрытии исходной клетки. SoundDef и его клипы заимствованы. Новые AudioListener не создаются; используется существующая маршрутизация пространственного звука. Произвольная акустика между картами этим не реализуется.

## Жизненный цикл вида

Новый Lifecycle(view, notification) сообщает Opened, Closing, MapChanged, ControlAcquired, ControlReleased, CarrierChanged, Paused, Resumed. Closing вызывается перед Dispose; Reason различает ViewClosed, MapChanged, MapRemoved, RegistrationRemoved, CallbackFailed. PreviousMap/PreviousPawn доступны для переходов. Исключение в Closing не отменяет освобождение ресурсов.

RetainOnMapTransfer сохраняет прежний смысл. Сохранённый экземпляр получает смену Map; пересозданный –  Closing(MapChanged), Dispose, затем Open/Opened нового экземпляра. Эти события не являются сериализатором. Постоянные предпочтения сохраняются через ModSettings, игровые данные –  у нативного владельца. Загрузка новой игры создаёт новые локальные экземпляры, а не восстанавливает старые transient handles.

## Диагностика и возможности

ReportFault(area, id, exception, disabled) позволяет мосту добавить собственную ошибку в тот же отчёт. RimVisionDiagnostics.GetRegistrations возвращает снимок area/ID/priority/type. CurrentCameraProvider показывает primary-провайдера, GetInputBlocks –  расширения с активными блокировками, GetFaults –  последние ошибки (до 128, по последней ошибке area/ID). Disabled относится к отключению в том виде/экземпляре, где произошла ошибка; это не глобальный запрет регистрации. Describe собирает текстовый отчёт. Он доступен также кнопкой «Диагностика API» в настройках управления. Снимки диагностик создаются по запросу, не каждый кадр.

TryGetFeatureVersion(string, out Version) проверяет отдельные контракты:

`camera.lifecycle`, `camera.volume`, `input.gestures`, `input.axes`, `jobs.lifecycle`, `interactions`, `models`, `animation.events`, `effects`, `view.lifecycle`, `diagnostics`, `multiplayer.contracts`.

Версия этих новых возможностей –  1.0.0; версия общего API –  1.6.0. Как и раньше, проверка версии не позволяет JIT загрузить отсутствующий на старой DLL тип: необязательные мосты разделяйте до обращения к новым типам.

RegisterContract(id, version, multiplayer=true) объявляет версию собственного контракта аддона. GameplayFingerprint включает версию API, ID/priority игровых реестров actions/control/combat/spatial и требуемые MP-контракты. Камера, модели, HUD и локальные привязки его не меняют. Явно регистрируйте контракт, если меняете смысл обработки при прежнем ID, настройки симуляции или стороннюю игровую интеграцию. Состав игровых регистраций должен совпадать и оставаться стабильным в сессии.

Обновлённый MP-аддон отправляет отдельное диагностическое сообщение ApiContract после Claim и при изменении fingerprint. Несовпадение даёт локальное предупреждение и запись в диагностике; это не автоматическое одностороннее разрешение/запрет игровых команд. Локально вычисленный отказ не используется для ветвления симуляции. Fingerprint не заменяет штатные проверки модов Multiplayer, проверку DLL, регистрацию sync methods или синхронизацию настроек. Прежние игровые пакеты и Scribe-ключи не расширены; новые предпочтения ввода сохраняются только в ModSettings.

## Пример

[AdvancedExample.cs](Example/Source/AdvancedExample.cs) подключается явно через AdvancedExample.Register(). Он показывает удержание ремонта, отслеживание Job, Ctrl+R, внешний аналоговый источник, замену модели и эффект полученного урона. Действие ремонта предоставляет прежний ExampleMod; пример не регистрирует его повторно. Параметры оси и имени Def необязательны; глобальная автоматическая замена моделей не включается.
