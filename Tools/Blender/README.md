# RimVision Model Tools 0.4.35

Интерфейс поддерживает русский и английский. Переключатель «Язык» расположен
вверху панели RimVision и в настройках аддона. По умолчанию используется язык
Blender; для других языков интерфейс плагина отображается на английском.
Переключение не меняет язык самого Blender. Названия модов, ThingDef и пользовательских
моделей сохраняются как в исходных данных.

The interface supports English and Russian. The Language selector is available
at the top of the RimVision panel and in addon preferences. By default it follows
Blender; other Blender languages use English. Content state and Model status are
independent filters and can be combined with search, category and mod selection.

Аддон для работы с моделями RimVision непосредственно в Blender. Unity и запуск
RimWorld не нужны. В готовый ZIP включён экстрактор игровых ресурсов для
Windows x64 с Python 3.11 и 3.13, включая установленный Blender 5.2.
Зависимости выбираются автоматически по версии Python и распаковываются в отдельный
кэш для каждой версии. Сам аддон требует Blender 4.2+.
На другой платформе или с другой версией Python для извлечения ресурсов нужен
UnityPy 1.20.26 в окружении Blender; каталог обычных PNG и XML-моделей работает
без него. Работа в интерфейсе Blender и игре пока не проверена запуском.

## Установка и начало работы

Строки каталога всегда имеют четыре равных столбца: название, ThingDef,
состояние мода и статус модели. Пустые статусы оставляют свою ячейку пустой.
Для **TorchWallLamp** доступен готовый XML-шаблон прежнего настенного факела
с точкой огня: загрузите модель, отредактируйте и сохраните в свой аддон.
Для замены настенного факела в игре нужна обновлённая DLL RimVision.

Записи выключенных модов и DLC в каталоге показаны серым с отметкой «Выкл.».
Выбор «Мод» открывает отдельный список с такими же отметками и приглушёнными
именами выключенных пакетов. Все записи остаются доступными для выбора.

Разделы рабочей панели: **Игра и пути**, **Аддон**, **Модели аддона**, **Каталог**,
**Текущая модель**, **Материал и текстуры**, **Огонь и свет**, **Референс в сцене**,
**Сохранение и экспорт**. При открытии одного основного раздела остальные
автоматически сворачиваются. Сохранение всегда находится внизу панели.

Модели открытого аддона находятся в отдельном разделе **Модели аддона** после
управления аддоном в рабочей панели. Здесь же загрузка модели, обновление списка,
добавление выделенного и сохранение коллекции. Раздел развёрнут по умолчанию и сворачивается независимо
от управления аддоном. Создание, открытие и метаданные остаются в разделе аддона.

«Открыть аддон» начинает выбор папки в `RimWorld/Mods`, если игра найдена.
Если путь игры ещё не задан, кнопка сначала использует обычный автопоиск.

Для обновлений через Blender Extensions добавьте Remote Repository в
Preferences → Get Extensions → Repositories:
`https://papaya121.github.io/RimVision-Blender/index.json`.
После публикации репозитория найдите RimVision Model Tools и нажмите Install.
Включите **Check for Updates on Startup** в настройках этого репозитория;
установка найденной версии выполняется кнопкой **Update**.
Перед переходом сохраните .blend и отключите обычный legacy-аддон rimvision:
две версии одновременно регистрируют одни и те же операторы.
Рабочие модели и кэш сохраняются отдельно от папки плагина.

Код Blender-плагина: GPL-3.0-or-later, текст в LICENSE. Сторонние wheel-пакеты
сохраняют собственные лицензии, перечисленные в THIRD_PARTY.md.

В новой сцене со стартовыми Cube, Camera и Light панель сначала показывает
«Начать работу». Кнопка скрывает стартовые объекты, сохраняя их в сцене, и открывает
подготовку игры и спрайтов. После успешной загрузки каталога и готовности кэша
автоматически открывается выбор аддона. Откройте найденный аддон, выберите папку
вручную или создайте новый –  после этого доступны все рабочие разделы, каталог
и текущая модель развёрнуты. Из выбора аддона можно вернуться к подготовке.
Отмена или ошибка извлечения спрайтов не переводит на следующий шаг. Сцены с уже
открытым аддоном или моделями RimVision сохраняют обычный рабочий интерфейс.

Панель состоит из сворачиваемых разделов: аддон, игра и пути, каталог, текущая
модель, референс, материал и экспорт. Они закрыты по умолчанию; нажмите заголовок,
чтобы открыть нужный раздел. Состояние разделов сохраняется в сцене Blender.
В «Игра и пути» отметка «Спрайты подготовлены» показывает наличие кэша исходных
и активных спрайтов и число доступных картинок. При извлечении отображается его
текущий статус; после смены путей или ModsConfig.xml обновите каталог, чтобы
проверить готовность кэша для новых настроек.
В разделе «Текущая модель» кнопка «Удалить куб, свет и камеру» очищает стартовые
объекты из базовой Collection и удаляет её, если она стала пустой. Модели RimVision,
референсы, изменённая геометрия куба и другие объекты сохраняются. Работает в
Object Mode; удаление можно отменить через Ctrl+Z.
Текстуры выбираются по активным модам из ModsConfig.xml и их порядку загрузки,
даже если каталог показывает все установленные моды. Выключенные ретекстуры не
заменяют референсы. Кэш зависит от активных папок контента; при смене набора модов
нажмите «Подготовить спрайты игры».
Подготовка также извлекает спрайты выключенных модов и DLC в отдельный индекс.
Они используются только для предметов своего выключенного пакета и не заменяют
текстуры активного контента. В карточке отмечено, если мод или DLC выключен.
После обновления до 0.4.15 повторно нажмите «Подготовить спрайты игры», чтобы
появились картинки установленного, но выключенного контента.
Старые модели RimWorld3DVR
без uvTextureSize импортируются по размерам исходных игровых спрайтов, а
предпросмотр использует активную ретекстуру. Уже искажённую UV-развёртку это
автоматически не исправляет: исходную готовую модель нужно загрузить заново.
В каталоге доступны два независимых фильтра: состояние контента (весь, включённый
или выключенный) и статус модели (все, готовая XML, без XML, встроенная заменяемая,
встроенная недоступная для замены, редактируемые или неподдерживаемые объекты).
Их можно сочетать с поиском, категорией и выбором мода.
Раздел «Аддон моделей» автоматически показывает найденные пакеты моделей из
Mods игры, Workshop всех найденных Steam-библиотек, локальной папки rimvision_addons
и выбранных рабочих папок. Признак пакета –  About/About.xml с packageId и папка
OptionalContent/RimVision/Models либо OptionalContent/RimWorld3DVR/Models. Пустые
созданные аддоны также отображаются; основной papaya.rimvision исключён.
В списке видны название, количество XML-моделей и статус в ModsConfig.xml.
Выберите запись и нажмите «Открыть выбранный аддон». «Найти аддоны» обновляет
список вручную; поиск также выполняется при запуске плагина и загрузке каталога.
Наличие XML и доступность замены –  отдельные статусы. Двери и вентиляция
помечаются «3D • замена недоступна»: текущий рендер обходит XML-модели этих
объектов. Стены, природные скалы и каменные обломки помечаются «Встроенная 3D»;
их можно заменить XML-моделью, но исходная геометрия из кода не импортируется.
Карточка предмета поясняет ограничение. Отметки определяются по определениям
каталога и текущему коду RimVision, без подключения к запущенной игре.
Для животных и механоидов каталог также читает PawnKindDef.lifeStages и берёт
bodyGraphicData взрослой стадии, если у ThingDef нет своего graphicData.
uiIconPath используется для миниатюры при наличии картинки. Для человекоподобных
пешек без отдельного спрайта отображается базовое тело из BodyTypeDef с пояснением;
полный портрет с головой, волосами и одеждой собирается игрой и здесь не создаётся.

1. Отключить прежнюю версию аддона, установить обновлённый `RimVision-Blender.zip`
   через Preferences → Add-ons → Install from Disk, включить RimVision Model Tools.
   Внутренние модули перезагружаются при повторном включении аддона, чтобы Blender
   не использовал старый каталог из памяти после замены файлов.
2. Открыть 3D View → N → RimVision. Плагин ищет Steam через реестр и обычные
   папки, читает libraryfolders.vdf и appmanifest_294100.acf. Он находит игру,
   Workshop во всех найденных библиотеках и ModsConfig.xml. Полный обход дисков
   не выполняется. Для переносной или нестандартной установки путь можно задать
   в «Пути и дополнительные настройки».
3. Развернуть раздел **Игра и пути** и нажать **Найти игру и загрузить каталог**.
4. Нажать **Подготовить спрайты игры** один раз. Упакованные текстуры Core, DLC
   и модов извлекаются в личный кэш Blender; папки игры не изменяются.
   Извлечение идёт в фоне, статус виден в панели, Esc запрашивает отмену.
   При повторном выполнении неизменившиеся PNG используются из кэша.
5. Открыть **большой каталог**, найти предмет по имени, ThingDef или моду.
   Доступны фильтры категории, мода и наличия готовой модели. В списке есть
   миниатюры и отметка готовой модели, в карточке –  крупный спрайт и размер.

Плагин читает установленный контент. Опция «Только активные моды» использует
ModsConfig.xml. При наличии этого файла определения сортируются по активному
порядку загрузки; неактивный контент в полном каталоге располагается после него.
Поддержано обычное XML-наследование, точная секция версии/default LoadFolders.xml
и простые IfModActive/IfModNotActive. В режиме полного каталога условия оцениваются
по установленным пакетам. XML-патчи, сложные условия, переводы и определения,
создаваемые C#-кодом, не воспроизводятся. Об этом явно сообщает статус каталога.

## Создать или открыть аддон в Blender

В верхнем блоке **Аддон моделей** нажать **Создать аддон** и ввести только название.
Папка создаётся в `Mods` найденной игры; если игра не найдена –  в пользовательской
папке скриптов Blender `rimvision_addons`. Полный путь показан в панели.
About.xml, уникальный packageId, версия игры, зависимость и загрузка после RimVision,
а также `OptionalContent/RimVision/Models` создаются автоматически.
В `Strings/RimVision/<packageId>/Models.txt` записывается список моделей: это
стандартный текстовый ресурс RimWorld, благодаря которому пакет с одними моделями
не считается пустым. Список обновляется при открытии аддона и сохранении моделей.

**Открыть аддон** позволяет выбрать существующий корень с `About/About.xml`.
В блоке **Название, описание и превью** можно изменить название мода и выбрать
картинку. **Редактировать описание** открывает отдельную область текстового редактора
Blender с многострочным текстом описания. После редактирования нажать **Сохранить
оформление аддона**: название и описание записываются в About.xml, картинка –  в
About/Preview.png. Изображения, поддерживаемые Blender, автоматически сохраняются
в PNG; превью видно в панели. packageId, зависимости и другие поля About.xml
сохраняются, папка мода не переименовывается.
Панель показывает все его XML-модели и варианты. **Загрузить модель** открывает
выбранную запись для редактирования; каталог игры должен содержать её ThingDef.
В сцене создаётся отдельная коллекция с названием аддона. Новые шаблоны и
импортированные модели автоматически попадают в активную коллекцию. Для своих
мешей есть **Добавить выделенное в коллекцию**: сначала выбрать предмет каталога.
При создании новой модели можно выбрать начальную форму: куб, цилиндр, конус,
UV-сферу, икосферу, плоскость или тор. Форма ставится на землю и вписывается в
площадь предмета; у круглых форм сохраняются пропорции. Можно также добавлять
любые меши обычными средствами Blender и включать их в коллекцию аддона.
После создания или загрузки модели новые меши из `Shift+A` автоматически становятся
её дочерними частями и привязываются к тому же ThingDef. Положение в сцене сохраняется.
Текущая модель показана в панели; автоматическую привязку можно выключить.
В Edit Mode примитив добавляется непосредственно в редактируемый меш обычным
способом Blender. При сохранении достаточно выделить основную модель или любую
из её частей: экспорт включает всю модель с дочерними мешами.
Уже существующие объекты сцены автоматически не привязываются.

В блоке поиска отдельно показано, найдены ли игра, Workshop и ModsConfig.xml,
а также загружен ли каталог предметов.

**Сохранить модель в аддон** записывает выделенные меши как модель выбранного
предмета. **Сохранить всю коллекцию** записывает её модели по их ThingDef и вариантам;
части с одинаковым ThingDef, фильтром графики и смещением высоты объединяются.
Настройки фильтра и смещения хранятся на объектах при импорте/создании/сохранении;
после изменения этих полей сначала сохранить выбранную модель.
Список XML обновляется после записи. Зависимости от исходных модов и DLC добавляются
в About.xml автоматически; существующие метаданные сохраняются.

Загруженную модель из активного аддона можно сохранять обратно без отдельного
разрешения на замену. Остальные записи в её XML сохраняются. Для замены другого
существующего файла нужно включить **Заменить существующий XML**. При ошибке
сохранения коллекции ранее записанные модели остаются на диске, число записанных
моделей показывается в сообщении. Сохранение `.blend` выполняется обычными
средствами Blender; XML записывает модели для игры.

## Открыть существующую модель

Для выбранного предмета плагин находит XML из установленных пакетов в
`OptionalContent/RimWorld3DVR/Models` и `OptionalContent/RimVision/Models`.
Предметы с найденной моделью отмечены **Кастомная 3D** в списке и **Есть кастомная
версия –  посмотрите её** в карточке. После сохранения модели в активный аддон
отметка и список вариантов обновляются сразу.
Выбрать вариант и нажать **Добавить готовую модель**. Основная команда добавления
использует найденную модель, если она есть; **Новая модель** создаёт пустой шаблон
для работы с нуля. Если готовой модели нет, карточка предлагает создать шаблон.
Кнопка **XML…**
позволяет открыть внешний файл; если в нём несколько вариантов выбранного
ThingDef, плагин предлагает выбрать вариант.

Чтобы читать модели из рабочей копии, в «Пути и дополнительные настройки» указать
**Папка мода с моделями** и нажать **Перечитать папки**. Выбирать корень мода с
`OptionalContent`, например `Mods/RimVision`, а не Unity-проект целиком.
Эти модели добавляются к установленным и получают приоритет при выборе основной
модели. Каталог показывает количество объектов с готовыми моделями.

Модель появляется как редактируемый меш с материалами и UV. Сохраняются
направления текстур, solidColor, tint, twoSided, turretTop, правила соединений,
фильтр графики и heightOffset. Якоря импортируются дочерними Empty, groundCutout – 
дочерним мешем с каркасным отображением. Для обратного экспорта достаточно выделить
основной меш: его вспомогательные дочерние объекты учитываются автоматически.

Если спрайт ещё не подготовлен, геометрию всё равно можно открыть. Исходные
пиксельные UV сохраняются в атрибутах меша. После извлечения спрайтов импортированным
моделям назначаются текстуры и восстанавливается видимая развёртка. До этого
не следует редактировать пустую UV-развёртку пиксельных граней.

## Атлас всех ракурсов

Игровые картинки и материалы получают понятные имена: например,
`RV | Alpaca | Север` и `RV | Alpaca | Атлас 2×2`. Хэши остаются во внутренних
именах файлов кэша, но не показываются как названия этих ресурсов Blender.
Кнопка **Навести порядок в ресурсах RimVision** переименовывает распознанные
старые ресурсы плагина и удаляет его неиспользуемые материалы и картинки.
Ресурсы с пользователями, Fake User, несохранёнными правками картинки и внешними
библиотеками сохраняются. Свои картинки и материалы с собственными именами
не очищаются. Очистку можно отменить через Ctrl+Z.

В «Материал и текстуры» выберите **Атлас всех ракурсов** и нажмите
**Обновить материал в сцене**. Игровые спрайты объединятся в одну текстуру 2×2:
сверху North и East, снизу South и West. В UV Editor разместите UV-острова
на нужных тайлах этой картинки. Ракурс для всего материала выбирать не нужно.
Разные размеры спрайтов дополняются прозрачными полями без изменения масштаба
пикселей. Недостающий боковой вид зеркалится из противоположного;
отсутствующие остальные виды остаются пустыми. Существующая UV-развёртка
автоматически не меняется. Для экспорта атласа нужна UV-развёртка.
PNG сохраняется в аддон через механизм своих текстур и читается игрой как
обычная текстура модели. При повторном импорте это **Своя текстура**.

## Референс в сцене

Референсы растений из файлового каталога учитывают размер взрослого спрайта
в 3D-рендере RimVision и множитель XML-модели (`drawSize.x × visualSizeRange.max`).
Поэтому размер картинки задаётся в координатах редактируемой модели, а не по
размеру клетки. Прозрачное поле снизу компенсируется: видимое растение стоит
на Z=0. После обновления перезагрузите каталог и обновите референсы. Готовые
меши не масштабируются автоматически; подгоните их под обновлённую картинку.

«Все доступные стороны» включено по умолчанию: направленные спрайты размещаются
вокруг рабочей модели в соответствующих плоскостях. Лицо модели направляйте
на север (+Y), хвост –  на юг (−Y). Передний референс расположен на юге,
задний –  на севере, оба обращены к модели. Подписи у картинок скрыты,
текст возле сетки с названием предмета, размерами и направлением севера сохранён.
Игровой спрайт South используется как вид лица, North –  как вид спины;
название файла описывает поворот персонажа в игре, а не направление модели Blender.
East и West –  боковые виды. Низ картинок выровнен по земле.
Если имеется только один боковой спрайт, противоположный вид зеркалится.
Отсутствующие передний и задний виды не заменяются другой картинкой.
Общие отступ, смещение и прозрачность применяются ко всем видам.
Для ненаправленного спрайта сохраняется прежний одиночный референс. Отключите галочку,
чтобы вручную выбрать картинку, сторону размещения и поворот XYZ.
После обновления загрузите каталог заново для определения доступных направлений.

В одиночном режиме блока **Референс в сцене** можно выбрать сторону размещения (справа, слева,
север, юг, сверху или снизу), отступ и дополнительное смещение XYZ. Поворот XYZ
задаётся в градусах независимо от стороны. Сохранены прежнее положение
справа и поворот X=90°, Y=0°, Z=−90°. Изменения сразу обновляют референс, в том
числе созданный вручную при выключенном автоматическом референсе.

При выборе другого предмета каталога модели предыдущего предмета и их дочерние
объекты скрываются в текущем слое просмотра. При возвращении к предмету они
появляются снова с сохранёнными правками. Объекты, скрытые вручную до переключения,
остаются скрытыми; обычные объекты сцены и видимость при рендере не меняются.
Переключение работает и при выключенном автоматическом референсе.

При выборе предмета автоматически создаётся коллекция **RimVision References**:
сетка занимаемых клеток, подпись с направлением севера и доступные виды вокруг
рабочей модели либо одиночный спрайт. Режим и прозрачность меняются в панели.
Автоматическое обновление можно отключить и использовать кнопку
**Показать референс и сетку клеток**. Вспомогательные объекты не экспортируются
как геометрия и не участвуют в рендере. Обновление заменяет только помощники,
созданные плагином в этой коллекции; пользовательские меши сохраняются.

## Новая модель и экспорт

Раздел «Огонь и свет» содержит кнопки 🔥 «Огонь» и 💡 «Свет». Сначала создайте
или загрузите модель. Добавленная точка появляется над моделью: огонь обозначается
оранжевым контуром пламени, свет –  объектом Point Light. Выберите точку в списке,
перемещайте через G или задавайте координаты; удаление –  X. Для огня задаётся
размер и режим «Декоративный огонь –  горит всегда». В обычном режиме учитываются
топливо, питание и состояние игрового света, если эти компоненты есть у предмета.
Для лампы доступны оттенок игрового цвета, яркость и визуальный радиус.
Поддерживается одна точка каждого типа на модель. Они сохраняются в anchors XML
и восстанавливаются при повторном импорте; сохранение работает и при выбранной
точке вместо меша. Перемещение родительской модели перемещает точки вместе с ней.

Свет в игре работает у предмета с существующим игровым источником освещения:
добавление точки не добавляет CompGlower к ThingDef. Визуальные радиус и цвет
изменяют отображение существующего света, оставаясь в освещённых им клетках.
Питание, топливо и блокировка света стенами берутся из игры. При наложении ламп
направление освещения усредняется по их вкладу. Декоративный огонь –  визуальный
эффект, без урона или изменения игрового состояния. Предпросмотр света Blender
приблизительный. Для игры нужны обновлённые DLL RimVision и сборка шейдеров;
старые сборки эффекты из XML не читают. После установки обновлённого мода
перезапустите игру. Ограничения XML-моделей для отдельных рендеров сохраняются.

**Создать новую модель** добавляет куб с нужной площадью, материалом и референсом.
Один Blender unit = одна клетка. Земля –  Z=0, центр площади –  мировой (0,0,0),
север –  +Y, восток –  +X. Мировые трансформации и вычисленные модификаторы
учитываются при экспорте.

В настройках активного материала можно выбрать игровую текстуру, solidColor или
**Своя текстура**. Для своей текстуры выберите файл картинки, нажмите
**Обновить материал в сцене** и используйте UV-развёртку меша. Если выключить
**Export active UV map**, RimVision автоматически натянет картинку на каждую грань.
Разным граням можно назначить разные материалы с собственными картинками.
При сохранении изображения автоматически преобразуются в PNG и копируются в
`Textures/RimVision/Custom/` аддона; пути записываются в XML. Исходные файлы не меняются.
При загрузке готовой модели эти материалы и UV восстанавливаются из аддона.
Прозрачные участки PNG поддерживаются через отсечение по альфа-каналу.
Для игры нужна версия DLL RimVision с поддержкой `texturePath`; старый загрузчик
свои текстуры не читает. Произвольные Blender-шейдеры и анимации
не экспортируются.
Smooth, Auto Smooth / Smooth by Angle, резкие границы и результат модификаторов
нормалей экспортируются как итоговые нормали углов граней. Поворот, масштаб и
модификаторы меша учитываются. При импорте XML нормали восстанавливаются;
сам стек модификаторов и параметр угла не восстанавливаются, сохраняется их
визуальный результат. Для отображения сглаживания в игре нужна обновлённая DLL
RimVision с поддержкой normals. Старые XML без normals сохраняют плоскую
отрисовку. Освещение и шейдеры игры могут отличаться от Blender.
**Surface → Материал объекта** использует уже назначенный материал Blender,
не меняя его ноды при обновлении предпросмотра или каталога. Поддерживаются
однотонный Base Color у Principled BSDF и Image Texture, подключённая напрямую
к Base Color. Картинка копируется в аддон как PNG, включая упакованные изображения
и несохранённые изменения пикселей. Используется UV-карта из UV Map, либо активная
UV-карта меша; UV Texture Coordinate также поддерживается. Настройка двух сторон
берётся из Backface Culling материала. Цвет предмета применяется только при
включённом Tint with thing color. Режим выбирается отдельно у каждого материала.
Mapping, процедурные текстуры и сложные графы сначала нужно запечь в картинку.
BSDF-граф Blender, roughness, metallic и normal map не переносятся; в игре цвет
и картинка отображаются шейдером RimVision с поддержкой отсечения прозрачных пикселей.

Для Thing используется размер северного спрайта; если направления имеют разные
размеры, назначать конкретное направление. Экспорт сохраняет исходный размер
картинки в `uvTextureSize`, чтобы смена разрешения игровыми модами не сдвигала UV.
Для этого нужна обновлённая DLL RimVision. Форма рисунка в моде текстур всё равно
может отличаться от референса Blender.
Для игровых спрайтов UV вне 0–1 RimVision ограничивает
краями текстуры. Height offset сохраняется отдельным параметром игрового рендера;
высота вершин импортированного меша остаётся исходной.

В Object Mode выделить меши одной модели, указать корень отдельного мода и нажать
**Экспортировать модель**. Результат:
`<мод>/OptionalContent/RimVision/Models/<ThingDef>.xml`.
Мелкие треугольники допускаются. Грани с нулевой или почти нулевой площадью
останавливают экспорт с названием объекта и номером грани после модификаторов;
проверьте совпадающие вершины, схлопнутые грани и масштаб. Порог проверки мелких
деталей также обновлён в загрузчике игры и требует установки обновлённой DLL.
Для вариантов добавляется суффикс по фильтру графики. Исходные меши не меняются,
существующий XML по умолчанию не заменяется. About.xml нужно подготовить отдельно:
зависимость на `papaya.rimvision` и исходный мод, загрузка пакета после них.
Спрайты из кэша служат локальными референсами и не копируются в пакет моделей.

Экспорт поддерживает Building/Item, Plant и Pawn-животных, кроме дверей.
В каталоге животные находятся в категории Pawn, растения –  Plant. Создание,
импорт и сохранение в аддон работают теми же кнопками. Модель животного делайте
мордой вдоль +Y (север), ноги на Z=0; один Blender unit равен одной клетке.
В игре модель движется и поворачивается вместе с животным, не разворачиваясь
к камере. Для лежащего животного или трупа модель укладывается на бок.
На модели животного игровая текстура Thing берётся для North: UV-развёртка
остаётся привязана к мешу при его поворотах. Явные North/East/South/West сохраняются.
Модели растений масштабируются по игровому росту. Если подходящей модели нет
или её игровые текстуры недоступны, сохраняется прежняя отрисовка спрайтами.
Модель животного –  цельный меш без скелетной анимации ног; портреты и переносимые
животные сохраняют существующую отрисовку. Модели людей и механоидов не поддержаны.
После обновления загрузите каталог заново для определения животных; старый JSON
каталог без поля animal необходимо экспортировать заново или заменить загрузкой
из папок игры. Для игры требуется обновлённая DLL RimVision.
Специальные пути
отрисовки RimVision могут обходить модели: наличие записи каталога не означает
поддержку любого объекта. После изменения пакета моделей игру нужно перезапустить.

## Подготовка ZIP из исходников

`python Tools/Blender/package.py` проверяет синтаксис исходников и упаковывает
аддон с колесами зависимостей из `Tools/Blender/wheels`. Состав сторонних
компонентов описан в THIRD_PARTY.md; оригинальные лицензии сохранены в колесах.
