# Публикация обновлений

Публичный репозиторий: https://github.com/Papaya121/RimVision-Blender
Адрес для Blender: https://papaya121.github.io/RimVision-Blender/index.json

В репозитории лежат только исходники плагина, wheel-зависимости, документация,
лицензия и workflow. Игровые ресурсы и Unity-проект туда не добавляются.

1. Обновите исходники в `rimvision/` и необходимые зависимости в `wheels/`.
2. Увеличьте одинаково версию в `blender_manifest.toml` и `rimvision/__init__.py`.
3. Сохраните изменения в отдельном репозитории и отправьте в его `main`.
4. Workflow **Publish Blender extension** создаст ZIP, Release с тегом `vVERSION`
   и обновит Pages. Дождитесь зелёного статуса Actions.

Повторный запуск одной версии допускается только с идентичным содержимым ZIP.
Если содержимое изменилось, нужно увеличить версию: опубликованные версии
не перезаписываются. При ошибке Pages workflow можно повторить после исправления
настроек, не создавая ещё один Release.

Для локальной упаковки используйте Python 3.11+:

```powershell
python package.py --extension --output-dir dist
```

В `dist/` появятся ZIP расширения, `index.json` с SHA-256 архива и `index.html`.
Без `--extension` создаётся прежний legacy `RimVision-Blender.zip`.

Первичная настройка Pages: Settings → Pages → Source → GitHub Actions.
Workflow использует встроенный GITHUB_TOKEN; дополнительных секретов не нужно.

Для Blender Extensions пользователь один раз добавляет Remote Repository,
включает Check for Updates on Startup и устанавливает плагин. Найденные обновления
устанавливаются штатной кнопкой Update. Плагин не заменяет сам себя во время
работы Blender. После обновления перезапустите Blender, если интерфейс предлагает это.

При переходе с legacy-аддона сначала сохраните .blend и отключите старую версию.
Кэш и создаваемые моды находятся вне папки установленного расширения.
Сохраняйте отдельную рабочую копию этого репозитория; изменения исходного плагина
в Unity-проекте нужно переносить сюда перед публикацией новой версии.
