# Модели для RimVision

Настенный факел TorchWallLamp использует редактируемую XML-модель из Models.
Исходная геометрия и точка огня перенесены в TorchWallLamp.xml. Аддон с моделью
того же ThingDef, загруженный после RimVision, заменяет её. Предпросмотр
строительства также использует XML. Если модель не найдена, применяется прежний
процедурный факел. Топливо, освещение и крепление к стене остаются игровыми.

В `anchors/li` поддерживаются эффекты `name=fire` и `name=light`, по одной точке
каждого типа. Координаты `x`, `height`, `z` задаются в тех же осях, что вершины;
поворот предмета и heightOffset применяются к ним вместе с моделью.
Для fire: `size` (0.05–5, по умолчанию 1), `always` (по умолчанию false).
Для light: `color` (RGB 0–1 через запятую, по умолчанию 1,1,1), `intensity`
(0–8, по умолчанию 1), `radius` (0.1–32, по умолчанию 8). Свет использует
существующий игровой источник и его проходимость через клетки; цвет является
множителем игрового цвета, радиус ограничивает визуальное распространение.
Огонь учитывает топливо, питание и активный Glower при наличии; always включает
постоянный декоративный эффект. Эти данные не изменяют игровую симуляцию.

Отдельный мод может добавлять модели для существующих ThingDef без своей DLL.
В About/About.xml укажите зависимость и загрузку после RimVision:

```xml
<modDependencies>
  <li>
    <packageId>papaya.rimvision</packageId>
    <displayName>RimVision</displayName>
  </li>
</modDependencies>
<loadAfter><li>papaya.rimvision</li></loadAfter>
```

Добавьте XML в `<корень вашего мода>/OptionalContent/RimVision/Models/`.
Plant и Pawn-животные используют тот же формат моделей и привязку thingDef.
В настройках RimVision кнопка «Животные и растения: 3D / 2D» переключает обе
категории между моделями и прежними спрайтами. По умолчанию включён 3D.
Настройка сохраняется; перезапуск не нужен, растения обновляются вместе с чанками.
Масштаб растения –  `graphicData.drawSize.x × visualSizeRange.LerpThroughRange(Growth)`,
как в игровом рендере растений. Масштаб животного берётся из текущего
BodyGraphic.drawSize (большая из двух сторон) и меняется с возрастной стадией.
Это множители размеров вершин XML, а не замена заданных в модели пропорций.
Модель животного перемещается и
поворачивается по игровому направлению, лежащие животные и трупы укладываются
на бок. Базовое направление морды –  север (+Y в Blender, +Z в Unity).
Если модель отсутствует или её игровые текстуры недоступны, остаётся прежний
рендер спрайта. Модель цельная, без скелетной анимации; люди, механоиды,
портреты и переносимые животные продолжают использовать свои существующие пути.
Прицеливание в модель животного проверяет её треугольники с учётом поворота
и прозрачности текстуры. Ручные пули в одиночной игре используют ту же проверку;
Multiplayer сохраняет существующую синхронизированную проверку объёмов.
Подпапки поддерживаются. Совместим и прежний путь
`OptionalContent/RimWorld3DVR/Models/`. Пути считаются от корня мода;
версионные папки и LoadFolders.xml для этих данных не обрабатываются.
Не кладите эти XML в обычную папку Defs: их читает загрузчик RimVision,
а не штатный загрузчик DefDatabase. Имя элемента внутри Defs произвольное;
старое имя RimWorld3DVR.Render.Rim3DModelDef также поддерживается.

Минимальный пример объёмного корпуса для табурета:

```xml
<?xml version="1.0" encoding="utf-8"?>
<Defs>
  <RimVisionModel>
    <thingDef>Stool</thingDef>
    <heightOffset>0</heightOffset>
    <vertices>
      <li><x>0</x><height>0</height><z>0</z></li>
      <li><x>0</x><height>0</height><z>1</z></li>
      <li><x>1</x><height>0</height><z>1</z></li>
      <li><x>1</x><height>0</height><z>0</z></li>
      <li><x>0</x><height>0.6</height><z>0</z></li>
      <li><x>0</x><height>0.6</height><z>1</z></li>
      <li><x>1</x><height>0.6</height><z>1</z></li>
      <li><x>1</x><height>0.6</height><z>0</z></li>
    </vertices>
    <faces>
      <li><indices>4,5,6,7</indices><texture>Thing</texture></li>
      <li><indices>3,2,1,0</indices><solidColor>0.5,0.4,0.3</solidColor><tintWithThing>true</tintWithThing></li>
      <li><indices>0,1,5,4</indices><solidColor>0.5,0.4,0.3</solidColor><tintWithThing>true</tintWithThing></li>
      <li><indices>1,2,6,5</indices><solidColor>0.5,0.4,0.3</solidColor><tintWithThing>true</tintWithThing></li>
      <li><indices>2,3,7,6</indices><solidColor>0.5,0.4,0.3</solidColor><tintWithThing>true</tintWithThing></li>
      <li><indices>3,0,4,7</indices><solidColor>0.5,0.4,0.3</solidColor><tintWithThing>true</tintWithThing></li>
    </faces>
  </RimVisionModel>
</Defs>
```

`thingDef` –  точное имя игрового определения. Неизвестные ThingDef пропускаются,
поэтому модели для отсутствующих DLC не мешают загрузке.
Вершины задаются в единицах клеток: x/z от угла занимаемой площади,
height –  высота. Индексы начинаются с нуля. Грани должны быть выпуклыми,
с вершинами в порядке обхода; нормаль вычисляется из этого порядка.

Параметры модели:

- `heightOffset` –  дополнительное смещение по высоте, по умолчанию 0.
- `graphicPathContains` –  необязательная подстрока пути игровой текстуры,
  без учёта регистра. Позволяет задавать варианты для стилей и разных график.

Параметры грани:

- `texture`: Thing (текущее направление объекта), North, East, South, West.
  Используются игровые материалы объекта с его цветом и стилем.
- `solidColor`: RGB от 0 до 1 через запятую, вместо текстуры.
- `texturePath`: своя текстура, путь относительно `Textures/` без расширения,
  например `RimVision/Custom/my_model` для файла `Textures/RimVision/Custom/my_model.png`.
  Используется вместо `texture` и не совмещается с `solidColor`. UV считаются от
  размеров своей картинки; `tintWithThing` использует основной цвет игрового
  графического материала, включая окраску шерсти животных. Если материал не
  задаёт цвет, используется `Thing.DrawColor`.
  Прозрачность поддерживается отсечением по альфа-каналу. Названия путей должны
  быть уникальными среди активных модов; плагин Blender использует хеш картинки.
  `tintWithThing=true` умножает этот цвет на цвет объекта.
- `twoSided`: true по умолчанию; false включает отсечение обратной стороны.
- `turretTop`: true для граней подвижного оружия Building_TurretGun. Вершины задаются относительно той же площади, что и основание; оружие поворачивается вместе с игровым наведением.
- `uvPixels`: x0,y0,x1,y1 –  прямоугольник в пикселях исходной текстуры.
- `uvPoints`: x,y;x,y;… –  пиксельные координаты для каждой вершины грани.
- `normals`: nx,ny,nz;… –  нормали для каждого угла грани в порядке `indices`;
  оси такие же, как у вершин модели: X, высота Y, Z. Нормали нормализуются при
  чтении; без поля используется геометрическая нормаль грани, как раньше.
  Плагин Blender сохраняет итоговые split normals для Smooth и Smooth by Angle.
- `smooth`: true/false –  режим сглаживания грани для обратного импорта в Blender;
  игровой рендер использует значения `normals`.
- `uvTextureSize`: ширина,высота картинки, по которой размечены пиксельные UV,
  например `64,64`. Позволяет сохранить разметку при замене текстуры на другое
  разрешение. Без этого поля действует прежнее определение размеров текстуры.
  Начало координат сверху слева. Без UV-параметров текстура проецируется на грань автоматически.
- `flipU` / `flipV`: true для отражения текстуры.
- `requiredLinks` / `forbiddenLinks`: направления соседних соединений
  North,East,South,West через запятую, для связанных построек.

Десятичный разделитель –  точка.

Приоритет: среди подходящих моделей выигрывает мод ниже в списке загрузки.
В пределах одного мода выбирается самый длинный подходящий graphicPathContains;
модель без фильтра используется, если нет подходящего варианта этого мода.
Если поздний мод не содержит подходящего варианта, остаётся модель раннего мода.
Одинаковые thingDef + graphicPathContains заменяются последним прочитанным описанием.
Файлы читаются в порядке имён; прежняя папка RimWorld3DVR читается перед RimVision.

Файлы читаются при первом обращении к библиотеке моделей и сохраняются в памяти
3D-вида; покадрового чтения файлов нет. Геометрия включается в общие меши чанков.
После установки или изменения пакета моделей перезапустите игру.
Некорректные модели пропускаются с предупреждением и путём файла в игровом логе.

Этот формат обслуживает обычные постройки и предметы. Растения, двери,
напольные маркеры и объекты со специальной отрисовкой (например, вентиляция)
сохраняют свой отдельный путь рендера.
FBX/OBJ, префабы, анимации и собственные текстуры граней этим форматом не загружаются.
