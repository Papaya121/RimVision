# Камера, анимации, HUD и ввод –  API 1.5

Эти контракты дополняют [основное руководство](README.md). Они требуют исходников/DLL API 1.5 и обновлённого Multiplayer-аддона. Существующие провайдеры и сигнатуры сохранены. Основной мод, Multiplayer-аддон и отдельный аддон третьего лица собраны 22.10.2026; проверка в игре не выполнялась.

## Камера

`RimVisionCamera.RegisterProvider(id, provider, priority)` выбирает первый подходящий `RimVisionCameraProvider`. После него `RegisterModifier(id, modifier, priority)` последовательно применяет все подходящие модификаторы. В каждом реестре порядок прежний: больший priority раньше, затем ordinal ID. Регистрации возвращают IDisposable. Невалидный результат или исключение оставляет предыдущий корректный кадр.

Реализуйте `Handles(RimVisionCameraContext)` и `Evaluate(context, ref RimVisionCameraFrame)`. Контекст содержит Map, Pawn, ActorPosition, Focus, Yaw, Pitch, Distance и DeltaSeconds. Mode –  флаги Overview, Pawn, Mortar, Falling, Transition. Pawn означает режим управления персонажем; камера этого режима может находиться за спиной, сбоку или в иной точке. Transition дополняет основной режим. Провайдер явно выбирает, какие специальные режимы он заменяет.

| Поле кадра | Назначение |
| --- | --- |
| Pose | Позиция и поворот камеры в координатах активной карты. |
| FieldOfView | Перспективный FOV, от 1 до 179 градусов. |
| NearClip, FarClip | Положительные плоскости отсечения, FarClip > NearClip. |
| Orthographic, OrthographicSize | Ортографическая проекция и её положительный размер. |
| Pivot, AvoidObstacles, ObstaclePadding | Опорная точка и сокращение отступа камеры при пересечении отображаемых поверхностей, зданий и деревьев. |
| ShowBody, ShowFirstPersonItems | Видимость управляемого тела по умолчанию и FPV-прохода предметов/кистей. Окончательная видимость тела также проходит presentation providers и обязательные ограничения карты. |
| AimFromActor | Наведение из камеры, выстрел от позиции глаз персонажа к найденной точке. |
| MovementYaw | Направление, относительно которого интерпретируется WASD; позволяет отделить движение от визуального поворота камеры. |
| PitchLimits, LookSensitivity, AllowLook | Ограничения и множитель штатного мышиного обзора. |
| CaptureMouse | Разрешение штатного захвата курсора. Без захвата обычные FPV-клики не исполняются; собственный интерфейс использует registered actions. |
| OrbitDistance, ZoomLimits, AllowZoom | Состояние дистанции, положительные пределы и разрешение штатного колеса. Изменённая дистанция доступна следующему контексту как Distance. |
| OverrideListener, ListenerPose | Необязательная отдельная локальная поза существующего аудиослушателя. |

Порядок: штатная камера и её эффекты → прежний CameraPose для обычного pawn-режима → штатный переход → новый camera provider → camera modifiers → ограничение отступа → применение проекции и расчёт луча выстрела. Ограничения мыши/движения читают последний вычисленный кадр; это не синхронизированное состояние. Для кинематографической камеры задавайте абсолютную Pose; для свободной камеры можно отключить захват, изменить фокус собственными локальными вычислениями и работать в Overview. Запреты игрового управления, пауза, доступность пешки и проверки команд продолжают действовать независимо от визуальной камеры.

`RimVisionCamera.ThirdPerson(context, ref frame, shoulderOffset, distance)` задаёт камеру за персонажем с плечевым смещением, показывает тело, скрывает FPV-предметы, включает препятствия, наведение от персонажа и звук у опорной точки. Для переменной дистанции передавайте ограниченный `context.Distance`. Сам персонаж и его нативный Carrier исключаются из выбора препятствий/точки выстрела. Это визуальная проверка, не новая физическая симуляция. Провайдер атаки повторно проверяет точку выстрела, LOS и нативную геометрию при исполнении.

`FirstPerson` в старом RimVisionViewState сохраняет значение режима управления пешкой и остаётся true при третьем лице. Для фактического представления читайте BodyVisible, FirstPersonItemsVisible, CameraPosition/Rotation, FieldOfView, Orthographic/Size, CameraTransition и Falling. `AimRay` –  уже согласованный луч выстрела; он может отличаться от луча из камеры. Для выбора экранной точки используйте `view.TryCreateRay(guiPosition, viewport, out ray)`; метод поддерживает обе проекции и возвращает координаты активной карты.

Полный пример переключаемого третьего лица, собственного прицела и клавиши K находится в [PresentationExample.cs](Example/Source/PresentationExample.cs). `PresentationExample.Register()` вызывается явно; пример не активируется при загрузке основного ExampleMod.

## Поза и анимации

У `RimVisionPresentationProvider` добавлено свойство `Channels`: Visibility, PawnPose, CameraPose, PawnAnimation, WeaponAnimation. Значение по умолчанию Legacy сохраняет выбор старых провайдеров для Visibility/PawnPose/CameraPose. Для каждого канала первичный обработчик выбирается отдельно. Укажите только реально реализуемые каналы.

`RimVisionPresentation.RegisterModifier` применяет все подходящие модификаторы после первичного обработчика своего канала. Их порядок –  priority по убыванию, затем ID. Камера, посадка и оружие могут использовать разные каналы, а добавочные визуальные смещения –  отдельные модификаторы. Не используйте визуальные callback для игровых мутаций.

`PawnAnimation(context, ref RimVisionPawnAnimationFrame)` получает исходную позу перед штатным покачиванием ходьбы. Можно изменить Pose, Scale и AnimateWalk. После него при AnimateWalk=true применяется штатная ходьба, затем прежний PawnPose. Новое поле Scale поддерживает отрицательные компоненты для отражения, но запрещает нули и нечисловые значения. Это визуальный масштаб; нативные размеры и физические попадания не меняются.

`WeaponAnimation(context, ref RimVisionWeaponAnimationFrame)` вызывается после штатных позы, прицеливания, отдачи и покачивания предмета. Контекст содержит Pawn, Item, Map, Observer, FirstPerson, Carried, AimBlend, Recoil, MeleeStartedTick, Moving, Sprinting, Sneaking, Tick, TickFraction, DeltaSeconds и Paused. FirstPerson здесь означает именно FPV-проход, а не старый флаг режима управления из ViewState. Для мира контекст использует координаты карты; для FPV –  координаты камеры.

| Поле оружия | Координаты и смысл |
| --- | --- |
| Pose, Scale | Поза и масштаб всего предмета в карте либо камере. |
| RightHand, LeftHand | Локальные позы кистей относительно предмета, до применения его масштаба. |
| RightHandScale, LeftHandScale | Локальные масштабы кистей относительно предмета. |
| Muzzle | Локальная точка дула относительно предмета. Используется визуальными вспышками/трассерами, не авторитетным уроном. |
| DrawItem, DrawRightHand, DrawLeftHand | Независимая отрисовка предмета и кистей; анатомия определяет исходные значения. |
| Mesh, Material | Необязательная замена меша/материала в FPV-проходе. В мировом проходе эти два поля не применяются. |

FPV-материал должен поддерживать `_Rim3DFirstPersonProjection` и семантику прохода. Матрица передаётся через MaterialPropertyBlock, заимствованный материал не изменяется. Mesh/Material не передают владение рендереру: создавайте их через OwnResource либо освобождайте у своего владельца. Отдельная модель в мире создаётся через объекты расширения и точки крепления. После снятия регистрации штатные позы и точки хвата восстанавливаются следующим обновлением.

Штатная карточка гуманоидов не является скелетной моделью и не содержит костей конечностей. Для собственной анимации частей тела создайте свою иерархию GameObject/мешей через расширение, скройте стандартную карточку через Visibility и обновляйте собственные дочерние Transform/Animator в BeforeRender. API не добавляет несуществующие кости ванильному спрайту. Визуальный пикер учитывает Scale карточки/модели; для лежащих в кровати пешек остаётся прежний объём над матрасом; прежний SP-путь ручной пули продолжает использовать прежнюю геометрию без нового масштаба, а MP –  существующий детерминированный полёт и переданную высоту цели.

### Точки крепления

`view.TryGetAttachment(pawn, socket, out RimVisionAttachmentPose)` читает Body, Weapon, RightHand, LeftHand или Muzzle в координатах активной карты. Результат включает Pose, Scale, Visible и CanDraw. Visible учитывает скрытие стандартного элемента; CanDraw сохраняет обязательные ограничения spawned/map/fog/spatial visibility. Данные относятся к текущим визуальным объектам, не физическим hitbox.

`CreatePawnAttachment(pawn, socket, name, offset, followDefaultVisibility=true)` создаёт объект в собственном поддереве расширения. API обновляет его размещение перед BeforeRender; анимируйте дочерние элементы, поскольку положение корня принадлежит привязке. При временном отсутствии точки объект скрыт, при возвращении точки снова обновляется. При замене стандартной модели используйте followDefaultVisibility=false: скрытие ванильной карточки не скрывает вашу замену, но CanDraw продолжает действовать. Созданные объекты и переданные ресурсы очищаются прежним владельцем RimVisionView.

## HUD

`RimVisionHud.RegisterProvider(id, provider, priority)` регистрирует локальный провайдер. Реализуйте Handles(context), при необходимости Layout(context, ref layout) и Draw(context, layout, phase). Все подходящие layout callbacks выполняются по priority/ID, затем Draw вызывается с Before и After вокруг штатного элемента. Восстанавливаются RNG и основные GUI/Text параметры; исключения изолируются.

Элементы: Scope, Activity, Immersion, Time, Messages, Character, Needs, Acceleration, Minigame, Controls, Resources, Help, Crosshair, CombatFeedback, Letters, Extensions, Mortar, Fall. У Character есть отдельные вложенные элементы Portrait, Weapon, Colonists, Health, Pain и Stamina; Time содержит Compass. Скрытие родителя скрывает и его штатных детей. Старый DrawHud расширений остаётся элементом Extensions и сохраняет прежний порядок.

Layout содержит:

- Viewport –  область, передаваемую штатной разметке элемента; её смещение позволяет перемещать отдельные панели.
- Visible –  рисовать ли элемент вообще, включая callbacks Draw.
- DrawDefault –  рисовать ли штатное содержимое между Before/After; false позволяет заменить его своим.
- Interactive –  доступность управления собственным интерфейсом. Исходно true в обзоре либо при освобождённом курсоре.
- InputBounds –  прямоугольник собственного интерфейса, который не должен пропускать мышь в обзор, стрельбу и взаимодействие.
- Bounds –  фактическая область панели либо объявленная область собственного содержимого. Штатные портрет, оружие, показатели, колонисты, потребности, ресурсы, часы и компас сообщают свои границы.

Все прямоугольники задаются в GUI-координатах, не пикселях RenderTexture. `view.TryGetHudLayout(element, out layout)` читает последнюю разметку текущего/предыдущего кадра; отсутствующие/скрытые элементы возвращают false. Для штатных панелей Bounds становятся известны после их отрисовки; до первого Repaint могут быть пустыми. У произвольного собственного элемента задавайте Bounds сами. Это позволяет размещать дополнительные шкалы рядом с занятыми областями без доступа к HudPresentation.

Штатный screenshot/HideInterface скрывает обычный интерфейс. Mortar/Fall имеют собственные элементы и сохраняют специальные ограничения. Draw вызывается в IMGUI, включая события ввода; игровые команды отправляйте через RequestAction/SubmitAction. Не меняйте Jobs и игровые значения из Layout/Draw.

## Клавиши и блокировки

`RimVisionInput.RegisterBinding(id, label, primary, secondary, channel, available, handle, priority)` добавляет две переназначаемые клавиши в настройки и справку F1. Разрешены клавиши клавиатуры кроме Escape/F1/F11; мышь сохраняет свои штатные функции. Назначения сохраняются по namespaced ID в ModSettings, поэтому переживают временное отсутствие аддона и входят в общий сброс управления.

available получает актуальный RimVisionViewState. handle получает состояние и фазу Pressed, Held, Released либо Cancelled; true поглощает обе назначенные клавиши на этот кадр для следующих аддонов и штатных действий. Held здесь локальный кадровый callback, не симуляционный тик. При потере фокуса, блокировке, смене доступности, снятии регистрации или закрытии вида удержание получает Cancelled. Исключение отключает эту привязку для текущего вида. Коллизии разрешаются порядком priority/ID.

`view.BlockInput(channels)` возвращает независимый IDisposable. Каналы: Movement, Look, Combat, Interaction, Shortcuts, All. Старый BlockInput() эквивалентен All. Блокировки применяются к локальному вводу, не запрещают явно отправленные registered actions и не заменяют игровую валидацию. Look также освобождает захват курсора. Держите handle только пока открыт интерфейс; повторное Dispose безопасно. Несколько блокировок суммируются у прежнего владельца RimVisionView.

`view.RequestControl(pawn)` и `RequestOverview()` ставят переход в очередь после локальных callback. Есть статические эквиваленты RimVisionApi для обработчиков клавиш без ссылки на view. Существующие правила захвата управления, Multiplayer ownership, pawn lock и переходов сохраняются; true означает принятие локального запроса, не гарантию захвата.

## Состояния, события и команды

Снимок вида дополнен Weapon, HeldItem, AimBlend, Recoil, Stamina, Sprinting, Sneaking, Moving, Acting, Resting, NativeControl, LastMeleeAttackTick, BlockedInput и параметрами камеры, перечисленными выше. Снимок локальный и предназначен для UI/анимаций. Состояние носителя сверх этих значений остаётся в нативном моде.

`RimVisionExtension.PresentationEvent(view, notification)` сообщает WeaponChanged, HeldItemChanged, AimStarted, AimEnded, Shot, Melee, MovementChanged и CameraChanged. Shot поступает из подтверждённого визуального feedback; остальные изменения сравниваются при обновлении сессии. Это локальные уведомления для эффектов, не источник сохранений/урона. Смена Pawn/Map и режима остаётся в StateChanged; события не обещают историю всех переходов между кадрами.

`SubmitAction(id, target, cell, value)` и `SubmitLayerAction(id, targetMap, target, cell, value)` возвращают RimVisionActionRequest. Статические варианты –  RimVisionApi.SubmitAction и RimVisionSpatial.SubmitAction; без открытого вида они возвращают null. У запроса есть RequestId, ActionId, Status, Reason и Completed. RequestAction со старым bool сохранён.

| Статус | Значение |
| --- | --- |
| Pending | Ожидается исполнение. |
| Succeeded | Выполнена нативная операция либо принят Job. Не означает завершение длительного Job. |
| Rejected | Запрос отклонён, обработчик вернул false или возникла ошибка. Reason может отсутствовать. |
| Cancelled | Локальный SP-запрос снят при закрытии/смене вида до исполнения. |
| Detached | MP-виду больше не принадлежит ожидание результата. Уже отправленная команда всё ещё может исполниться; этот статус не отменяет мир. |

`ActionCompleted(view, request)` вызывается вне синхронного исполнения и с восстановлением RNG. В MP отдельная команда проверяет owner/token, исполняет тот же валидатор/обработчик, а результат направляется только текущему владельцу. Нельзя интерпретировать отсутствие view или Detached как отмену сетевой команды. Отдельного публичного Cancel для уже отправленного запроса нет. Одновременно отслеживаются до 256 запросов на вид; уведомления также ограничены, статус завершённого объекта можно прочитать напрямую. В SP старые RequestAction и новые SubmitAction используют одну очередь с сохранением порядка. Старые command/Scribe форматы не расширяются.

## Нативное движение и пассажиры

Старые провайдеры по умолчанию сохраняют spawned Actor/Carrier на одной карте и XZ-позицию. Новые возможности включаются явно:

- SupportsContainedActor=true разрешает действующее лицо внутри нативного Carrier. Проверяется реальная цепочка ParentHolder до заспавненного носителя, а не произвольная ссылка. Принадлежность/состояние пешки и CanControl продолжают проверяться.
- SupportsVerticalMovement=true сохраняет Y из Position и передаёт Vertical/Input3D/Direction3D. Суммарный трёхмерный ввод нормализуется. Pitch/LookYaw/LookDirection передают независимое направление обзора; Yaw остаётся направлением пространства движения.
- CollectActors(map, actors) добавляет нативных действующих лиц в выбор пешек. Не очищайте переданный список. RimVision убирает недействительные/повторные добавления. Публичный RimVisionControl.CollectActors также доступен интерфейсам аддонов.

Ascend/Descend по умолчанию назначены на PageUp/PageDown. В MP вертикальная ось и независимые углы обзора передаются отдельной командой, а движение исполняется прежним контроллером на симуляционных тиках. RimVisionControl.MapFor(actor) разрешает текущую карту действующего лица через действительный нативный носитель. Сохранение связи Actor/Carrier, положения, посадки и нативных Jobs остаётся у мода-владельца. Вертикальный ввод –  transient состояние, не отдельная физика полёта.

Для находящегося в контейнере Actor стандартные пешие взаимодействия отключены: используйте registered actions, собственные клавиши/HUD и нативный боевой провайдер. Ядро не отправляет такого пассажира в ванильные пешие Jobs и не меняет его Position. Текущие Carrier/контекст заново проверяются в SP и MP, включая переход карты и восстановление после загрузки.

## Удерживаемая атака

Старый RimVisionCombatProvider сохраняет один Execute на нажатие. Для нового цикла переопределите UsesInputPhases=true, ValidateInput(context, phase) и Input(context, phase). Кнопка ЛКМ маршрутизирует Pressed, обновления цели, Released и Cancelled через отдельную команду. Пока удержание действительно, Input(..., Held) исполняется раз в симуляционный тик в SP/MP, а не по частоте кадров. false из Pressed/Held завершает цикл; провайдер должен корректно обрабатывать Cancelled и частично начатую операцию.

`RimVisionCombat.RequestInput(kind, phase, target, cell, aimRay, mode=0)` позволяет своим клавишам/HUD использовать тот же протокол, в том числе иной Mode или Melee. На действующее лицо допускается один активный цикл. При смене владельца/пешки/провайдера/карты, недоступности, потере ввода, паузе, закрытии или истечении срока входных данных выполняется Cancelled. Released/Cancelled доставляются исходному провайдеру без повторного запрета по cooldown/боеприпасам: это обязательный путь cleanup. Новое нажатие заменяет предыдущий цикл через Cancelled.

ValidateInput вызывается с восстановлением RNG; Input –  на авторитетной границе и может менять нативный мир. Проверяйте оружие, дистанцию, LOS, warmup/cooldown, цель, расход и допустимость Origin/Direction относительно носителя. Камера не является доверенным источником в MP. Нативный мод остаётся владельцем длительности заряда, очередей, урона и сохранений; transient удержание RimVision не сериализуется. После фактического выстрела `RimVisionCombat.NotifyShot(actor)` передаёт стандартный локальный/MP feedback для отдачи и событий. Не вызывайте его из чистой валидации.

## Выбор целей

У TryPick добавлена перегрузка с RimVisionPickFilter: маска Floor/Roof/Pawns/Buildings/Items/Plants/Plans, ExcludedThing и SolidOnly. Она использует прежний пикер активной и отображаемых карт, сохраняет обязательные ограничения видимости и не создаёт игровые hitbox. Ray и возвращаемая Point используют координаты активной карты; Map/Cell/Thing указывают настоящую карту цели. Для физической атаки используются нативные проверки синхронного исполнения.
